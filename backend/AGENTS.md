# 项目代码与注释规范

本项目以“维护者能够通过源码学习系统”为工程要求。新增或修改代码时必须遵守：

1. 模块 docstring 说明该文件负责什么、不负责什么，以及它位于哪一层。
2. 类 docstring 说明实体或组件的业务含义、生命周期和重要设计约束。
3. 公共方法 docstring 至少在适用时包含 Args、Returns、Raises；编排方法还要说明
   是否进行数据库、网络、Embedding 或向量库 I/O。
4. 逻辑注释解释“为什么这样做”、边界条件和隐含代价，不逐行翻译代码。
5. SQLAlchemy 实体必须说明表的业务粒度、主键/业务唯一键、外键、索引用途和
   relationship 与真实数据库列的区别；每个列继续使用数据库 `comment`。
6. Pydantic 实体的 Field `description` 要说明字段来源、是否可空、格式或后续用途。
7. LangChain Document/Chunk 的 `id`、`page_content` 和 metadata 字段必须说明来源、
   稳定性及是否进入 Embedding，避免数据库实体和 RAG 内存对象概念混淆。
8. 修改行为时同步更新 README、类型标注和测试。注释与实现冲突属于缺陷。
9. 避免无信息注释，例如“给变量赋值”“遍历列表”；名称已经表达清楚时不重复。
10. 注释默认使用中文，框架类名、字段名和业内固定术语保留准确英文名称。
