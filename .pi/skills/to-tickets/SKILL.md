这个 skill 把一份 spec 拆成一组**工单**：每条是一个 tracer bullet（垂直切片），并声明它被哪些工单阻塞。输入必须已经是一份写好的 spec；还没有的话先跑 `to-spec`。

工单写在 `docs/specs/` 下，与该 spec 同名（去掉 `.md`）：`docs/specs/NNNN-slug/issues/NN-<slug>.md`。**一个工单一个文件，绝不把所有工单合并写进一个文件**——合并文件既会打架，也让「哪个做完了」无法单独标记。

工单是施工期间的工件，与它来源的 spec 同生共死：验证通过后随 spec 一起删除，删除规则见根 `AGENTS.md` 的「完成条件」。**进度和验收勾选写在工单文件里**，spec 只写已经定稿的决策、不随施工进度改动。

## 处理流程

1. **拿上下文。** **输入必须是一份已经落成 `docs/specs/NNNN-slug.md` 的 spec**。老板传了路径就直接读全文；没传就去看 `docs/specs/` ——同时只有一个 spec 时就用它，有多份就问清楚是哪一份；一份都没有时，让老板先跑 `to-spec` 把它写出来。本 skill 不接「只活在对话里的计划」，因为工单目录靠 spec 命名、也靠 spec 一起删（见上），凭空拆出来的工单没有东西跟它同生共死。

2. **探代码库**（如果还没做过）。工单标题和描述沿用项目术语表（`CONTEXT.md`）的词汇，尊重相关区域的既有 ADR。同时找 prefactoring 的机会——「先把改动变容易，再做容易的改动」那类先行工作，它排在全部功能工单前面，不要混在中间。

3. **切垂直切片。** 每条工单要满足：

   - 切一条**又窄又完整**的路径，贯穿所有层（schema、API、界面、测试）——是垂直的，不是某一层的水平切片；
   - 完成当天就能单独演示或验证；
   - 尺寸压到一个全新的上下文窗口装得下——因为接手它的是一个从没见过这份 spec 的 session；
   - 给每条标出**阻塞边**：哪些工单必须先完成。没有阻塞的工单可以立刻开工。

   **宽重构是垂直切片规则的例外。** 宽重构指一次机械改动（改个列名、换掉共享符号的类型）波及全仓，一处改动同时弄坏成千上万个调用点，所以没有任何垂直切片能单独跑绿。这种不要硬套 tracer bullet，按 **expand–contract** 排序：先 expand，把新形式加在旧形式旁边，什么都不坏；再 migrate，按波及面分批（按包、按目录）把调用点迁过去，每批一条工单、都被 expand 阻塞，因为旧形式还在所以每批之间都保持绿；最后 contract，等没有调用方了再删旧形式，这条被所有 migrate 批次阻塞。连分批都保不住绿的时候，保留这个顺序，让它们共用一个集成分支，并全部阻塞一条最终的集成验证工单——绿只在那一条上承诺。

4. **反过来考老板。** 把切好的清单编号列出，逐条给出：

   - **标题**：简短有描述性；
   - **被谁阻塞**：哪些工单必须先完成；
   - **交付了什么行为**：这条工单让什么端到端行为跑起来。

   然后问三个问题：粒度对不对（太粗／太细）、阻塞边是不是真的（每条只该依赖真正卡住它的工单）、有没有该合并或该继续拆的。**老板点头之前不要落盘。** 这一步是纠正模型惯性的地方：模型天然倾向切成原子小步，动辄给三行改动切出十几条工单，这时就该合并。

   同时逐条自查两件事。一是**水平切片的味道**：对每条工单问「做完能演示什么」，答不上来、或者答案是「某一层代码」，那它就是水平切片，回去重切。二是**验收条件能不能失败**：对每条条件说出「什么观察能证明它是假的」，并确认在实现者起步的那个 commit 上它是红的；在起步点已经为真的条件、只能靠另一条工单的工作才能满足的条件、以及只是把需求复述一遍的条件，都是废条件，删掉重写。

5. **落盘。** 按第 4 步确认后的顺序写文件，编号从 `01` 起、按依赖顺序排（阻塞别人的排前面）。每条工单用下面的模板。

<工单模板>

# <NN>: <工单标题>

**要交付什么：** 这条工单让什么端到端行为跑起来，从用户视角说，不是逐层实现清单。

**被谁阻塞：** 拦住它的工单号／标题，或「无（可立刻开工）」。

**状态：** 待开工

- [ ] 验收条件 1
- [ ] 验收条件 2

</工单模板>

状态取值：`待开工`、`进行中`、`已完成`。

**不要**写具体文件路径、行号或代码片段，它们很快过时。例外：原型产出的片段比散文更精确地编码了某个决策（状态机、reducer、schema、类型形状）时，内联到相关决策下，并简要说明它来自原型——只截决策密集的部分，不要整段能跑通的演示。

## 拆完怎么跑

本 skill 到产出工件为止：不派发、不自动开工、不关单。跑哪些工单靠老板看清单自己数——没有未完成阻塞的那些就是当前可开工的，一条工单一个全新 session，中间清空上下文。工单的状态和验收勾选需要有人手工更新，否则「哪些做完了」立刻失准。

来源 spec 本来就已经定稿、不需要再拆的时候（改动一个上下文窗口装得下），不要用本 skill，直接动手。
