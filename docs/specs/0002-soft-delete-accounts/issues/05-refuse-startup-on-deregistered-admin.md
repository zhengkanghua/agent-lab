# 05: 启动时发现配置账号已注销就拒启动

**要交付什么：** 库里那个环境托管账号被注销之后，服务启动会直接失败并说清原因，而不是把它静默复活成一个能登录的超管。

**被谁阻塞：** 01（注销取代删除）

**状态：** 待开工

- [ ] 配置邮箱对应一个已注销账号时，启动同步抛错并说明「需要人工处理」
- [ ] 该场景有测试盯着，且打在真正的启动同步入口上（不是内部辅助函数）

**验收说明：** 启动同步的本意是恢复通道——超管全被锁在门外时改配置重启就能拿回入口，所以它会无条件把目标账号拉回「活跃的超管」。这正是不许静默复活的原因：它会把一个已注销的人变成能登录的超管。既不能静默复活，也不能静默跳过——跳过会让「配置的那个账号已注销」这个矛盾在没人知道的情况下失去入口。这条要打在真库上，宿主与「已注销账号登录被拒」那条同一份认证用例；顺带在那份文件里补上「已注销账号用正确密码登录失败、且文案与密码错误完全相同」。
