# 05: 启动时发现配置账号已注销就拒启动

**要交付什么：** 库里那个环境托管账号被注销之后，服务启动会直接失败并说清原因，而不是把它静默复活成一个能登录的超管。

**被谁阻塞：** 01（注销取代删除）

**状态：** 已完成

- [x] 配置邮箱对应一个已注销账号时，启动同步抛错并说明「需要人工处理」
- [x] 该场景有测试盯着，且打在真正的启动同步入口上（不是内部辅助函数）

**施工记录（2026-02）：**

- `bootstrap.py` 新增 `EnvironmentAdminDeregisteredError`；`_synchronize_once` 在「按邮箱找到目标账号」之后、任何写入之前检查 `deleted_at`，有值就 rollback 后抛错，消息里不出现邮箱。异常从 lifespan 里的 `environment_admin_sync()` 直推，因此服务启动直接失败。
- 登录被挡住分两层补上了：离线层在 `tests/test_auth.py` 新增「不可用账号登不进来、且与密码错误同一句话」；真库层在同一条新用例里拿正确密码真登一次，并断言两次响应逐字相同。
- 真库那条用例同时打真正的启动同步入口（`synchronize_environment_admin`），并断言被拒之后那一行一个字段都没被动过。
- 反证：把那条检查临时关掉再跑同一条用例，启动同步会尝试把 `is_active` 写回 true，被库上 `ck_users_deleted_at_implies_inactive` 抛 CheckViolation——也就是说改动前运维看到的是一条看不懂的约束冲突，而不是「需要人工处理」。
- 文档：后端架构说明的启动同步段与部署文档的轮换规则各补一句「配置邮箱指向已注销账号时拒绝启动」。

**已运行验证：** `uv run pytest -q`（761 passed, 67 skipped）；`RUN_POSTGRES_AUTH_INTEGRATION_TEST=1 uv run pytest -q tests/test_auth_environment_integration.py`（2 passed，真库）。

**验收说明：** 启动同步的本意是恢复通道——超管全被锁在门外时改配置重启就能拿回入口，所以它会无条件把目标账号拉回「活跃的超管」。这正是不许静默复活的原因：它会把一个已注销的人变成能登录的超管。既不能静默复活，也不能静默跳过——跳过会让「配置的那个账号已注销」这个矛盾在没人知道的情况下失去入口。这条要打在真库上，宿主与「已注销账号登录被拒」那条同一份认证用例；顺带在那份文件里补上「已注销账号用正确密码登录失败、且文案与密码错误完全相同」。
