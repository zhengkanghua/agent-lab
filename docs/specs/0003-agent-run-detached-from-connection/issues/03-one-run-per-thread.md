# 03: 一个会话同时只允许一次运行

**要交付什么：** 上一次运行还没结束时，同一个会话再提交会被明确拒绝（409 加稳定错误码 `agent_run_in_progress`），前端显示对应文案；不再出现两次运行互相覆盖、静默丢掉一次的情况。这条同时带来会话表新增两列的迁移：在途运行的 id、停止请求的时刻。

**被谁阻塞：** 01

**状态：** 待开工

- [ ] 会话在途时再次提交，返回 409 与 `agent_run_in_progress`（现在是：两次都受理，先完成的那次从历史里消失）
- [ ] 两次几乎同时提交时只有一个成功、另一个被拒（现在是：两个都成功）
- [ ] 运行结束之后同一会话立刻恢复可提交（现在是：没有「在途」这个概念）
- [ ] 新的一次运行占位时，上一次留下的停止请求已被清掉（现在是：没有这一列）
- [ ] 迁移可升可降；`last_active_at` 的列注释与相关决策记录同步成「最后活动时刻」
