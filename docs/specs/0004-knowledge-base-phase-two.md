## 问题陈述

系统已经具备通用 KnowledgeBase、Source、Document 和共享向量索引，但实际使用仍有新闻场景的限制：普通检索页面和 Agent 默认查新闻库，老板无法方便地选择所有知识库或其中几个，也不能上传自己的文本和 Markdown 资料。

现有 Agent 能取回资料并生成回答，但引用主要依赖模型在文字中写出文档编号，缺少程序可核对的引用关系。用户不能方便地确认一项结论依据哪个知识库、哪篇文档的哪段内容。全文 Tool 还把没有 Source 的 Document 视为不存在，不满足文件资料的读取需求。

会话回看是使用过程中的便利功能。老板接受早期消息被压缩后不再逐条回看，不需要为此增加独立的消息档案或文档历史版本。需要把这个限制正确体现在页面上，并明确旧回答与实时原文之间的关系。

## 解决方案

第二阶段交付以下能力：

- 普通检索默认选择所有启用知识库，也可明确选择一个或多个；结果和检索记录显示实际范围及文档归属。
- Agent 在当前会话内沿用老板选择的知识库范围，下一次提问前可以修改；检索和全文 Tool 都受本次运行范围约束。
- 超级用户上传 `.txt`、`.md` 文件，查看文件文档列表、内容和处理状态，并通过明确的“替换文件”操作更新同一篇 Document。
- 回答的关键事实结论关联实际取得的证据；能点击查看当前原文，资料不足时说明不足，推断明确标注。
- 会话继续复用现有 checkpointer。页面只提供未压缩问答的回看；原文更新时显示当前内容，删除时明确提示，旧回答不重新生成。
- 收尾新闻专用文案和通用文档的空字段展示，保留现有语义检索方式。

本阶段不加入关键词与语义混合检索、重排序、PDF/Word/OCR、粘贴录入、在线编辑、完整历史归档或新的权限体系。检索与回答质量仍需通过代表问题验收，不能把接口测试通过等同于事实回答正确。

## 用户故事

1. 作为知识库使用者，我想默认搜索所有启用知识库，以便不必先知道资料被放在哪个库。
2. 作为知识库使用者，我想选择一个或多个知识库，以便让检索只覆盖需要的资料。
3. 作为知识库使用者，我想看到当前查询范围，以便提交前知道会搜索哪些资料。

## 实现决策

### 1. 存储与权限边界

- 多个 KnowledgeBase 继续共用 PostgreSQL 的 Document 表和同规格 Qdrant Collection，通过 `knowledge_base_id` 表达归属与过滤范围。
- 保留现有通用 Collection/Alias 命名、Source 绑定、FreshRSS 增量同步、索引版本和清理范围规则。搜索默认所有知识库不改变定时清理的默认范围。
- 文件上传是新的资料导入入口，不要求创建虚假的外部 Source；上传 Document 的 Source、URL、外部稳定标识可以为空。
- 上传文档保存当前文本、实际格式和原上传文件名等最小展示元数据；文件名只是展示信息，不是文档唯一键。来源类型应能区分上传资料与外部同步资料。
- 仅增加文件管理、会话范围和引用关联实际需要的字段或消息元数据，不创建独立文档历史表、PostgreSQL Chunk 表、独立聊天归档或对象存储服务。
- 管理上传文档沿用超级用户权限；普通启用账号沿用检索与全文读取权限；Agent 沿用现有超级用户入口和会话归属校验。不新增知识库级账号授权模型。
- Agent Tool 继续只读知识数据。会话范围属于用户提交和应用编排的会话配置，不能通过模型调用写工具修改业务知识数据。

### 2. 普通检索的范围

- 页面初次进入默认“所有知识库”，这里的所有仅指当次解析出的启用 KnowledgeBase；显式选择支持一个或多个。
- 请求契约必须区分“所有启用知识库”与“明确选择的非空列表”。空列表、字段遗漏、目录加载失败都不能被解释为不带过滤条件的查询。
- 新页面显式发送范围；保留正在使用的旧 HTTP 单库参数及缺省 news 行为作为既有契约，不能仅通过改变缺省值使旧调用方悄然跨库。新旧范围同时出现且不一致时拒绝请求。
- 所有库模式在查询时解析启用 ID 集合；显式选择逐个检查存在与启用状态。未知、停用目标沿用稳定错误语义，不能静默忽略后扩大查询。
- 所有库模式解析为空时返回明确的无可用知识库结果，在 Embedding/Qdrant 前结束；底层范围过滤始终存在。
- 多库查询继续按 Document 分组并统一排序，不按库各取相同数量后简单拼接，也不保证每个知识库至少贡献一条结果。
- 每条检索记录保存提交时的选择模式、实际知识库集合及必要展示名称。此后改名、启停或切换当前选择，不改写历史记录和已经打开文档的实际归属。
- 请求开始后的配置变化按一次查询的范围快照解释；下一次查询重新解析。不得承诺配置变化能够撤回已经返回给用户的资料。

### 3. 上传、解析与文件查看

- 本阶段仅提供文件上传，支持 `.txt` 与 `.md`；不提供粘贴录入、在线编辑、PDF、Word、扫描件、压缩包、目录上传或网页抓取。
- 每个文件生成一篇 Document，并在上传时明确选择一个启用知识库；不通过文件名猜测知识库。先提供完整单文件流程，不把批量上传作为本阶段验收前置。
- 上传与替换共用格式、体积和文本有效性校验。支持 UTF-8 与 UTF-8 BOM；无法解码、空正文、不支持的格式、超过限制的文件返回明确错误，不用乱码替换后假装成功。体积上限在实现时集中配置并贯穿请求与页面提示。
- Markdown 保留当前文本中标题、段落、列表、代码块和表格文字的语义。采用成熟解析能力，不能用 RSS 清洗规则破坏代码缩进或有意义的重复内容，不手写 Markdown 解析器。
- 文件查看指在应用内打开当前文档内容。文本按文本展示，Markdown 使用现有安全渲染能力；原始 HTML 不执行，链接安全规则沿用现有约定。
- 只处理文件内已有文本；不自动下载 Markdown 外链、图片或关联文件，不对图片做文字识别。图片引用不作为图片内容已被理解的证据。
- 持久化一份可支持当前阅读与索引派生的文本事实，不为下载原始字节或逐版本回放增加附件归档。保留 Markdown 结构时，不再额外保存一套长期独立维护的正文副本。
- 管理列表至少包含标题、上传文件名、知识库、格式、更新时间和处理状态，并支持查看、替换及删除上传文档。默认标题由上传文件名生成，不增加独立的标题编辑功能。
- 文件无 Source、URL、作者或发布时间时显示真实空值对应的文案，不生成字符串 `None`、伪造来源或把上传时间当作发布时间。全文 Tool 必须能够读取没有 Source 的有效文档。

### 4. 新增与替换的身份规则

- 新增上传创建新的 `document_id`。同名或同正文的另一笔新增上传不自动合并、不覆盖旧文档，也不新增跨文档自动去重功能。
- 替换操作从已有上传文档发起，并显式携带目标 `document_id`。文件是否改名、正文是否改变，都不影响更新目标；不靠文件名、内容指纹或相似度推断对应关系。
- 替换成功后保留文档 ID 和 KnowledgeBase 归属，更新当前内容、文件展示信息与格式；引用仍指向同一文档。不支持通过替换把资料迁移到另一个知识库。
- 沿用 `content_hash` 判断处理后的正文是否变化；它不是原始文件字节指纹，也不是跨文档唯一身份。正文及其他可索引字段都不变时，不增加 `revision` 或重复索引。
- 标题、格式等可索引元数据变化仍须按现有 revision 规则处理，不能仅因正文 Hash 相同就忽略。具体进入 Payload 的字段保持单一契约。
- 替换先完成文件有效性校验，再提交业务更新；无效文件不破坏当前有效文档。并发替换应通过业务版本或等效条件检测冲突，不能让旧页面静默覆盖刚提交的新内容。
- 文件替换入口只作用于上传文档，不能覆盖由 FreshRSS 等外部 Source 维护的文档。
- 页面不自动重放结果不确定的新增上传请求；提交超时先提示核对列表。用户主动再次新增会形成新 Document，不能宣称新增操作按文件内容幂等。

### 5. 索引、失败与删除

- 新增上传，或正文及可索引字段发生变化的有效替换提交后，Document 进入既有待索引流程；完全无变化的替换不重新排队。区分“文件已保存”和“可以被检索”，通过既有索引执行端处理，不让上传请求长期等待全部 Embedding 完成。
- 复用持久化的待处理状态、条件认领、revision 检查和写资源协调，不能仅用进程内后台任务保存唯一处理机会，也不新建任务平台或消息队列。
- 索引执行端未运行时如实展示等待状态。接入与验收须验证处理实际发生，不能因为数据库插入成功就标记完整流程通过。
- 对索引失败展示脱敏原因并提供受控重试；重复索引或重试沿用原文档身份。索引失败不要求用户重新新增上传。
- 替换后索引尚未追上时沿用既有旧命中与当前正文 Hash 的区别，明确提示版本变化，不把旧向量命中标成新正文证据。
- 删除上传文档按明确 ID 操作，复用既有删除待办、Qdrant 确认与 PostgreSQL 条件删除顺序；覆盖待处理、索引失败和已索引文档，不依赖新闻的保留天数或只接收旧 indexed 候选。
- 删除与上传、替换、索引之间保留写协调。失败时保留可恢复状态；未确认 Qdrant 和业务删除完成前，页面不显示全部删除成功。
- 文件删除不清理知识库配置、外部 Source、账号、会话或其他文档。已有会话文本是否可见只受其自身压缩和会话生命周期影响。

### 6. Agent 会话范围与 Tool

- 新会话默认所有启用知识库。用户可以通过页面选择一个或多个库；当前选择在会话中持续生效，重新打开该会话也能恢复，不仅存在于组件内存。
- 下一次提问前可以修改选择。服务端为每次运行确定范围快照，开始后页面的选择变动只影响下一次运行；历史回答保留其当时范围。
- 用户在提问中明确提出更窄范围时应遵守，并让最终生效范围可见。范围有歧义时询问，不猜知识库身份；需要扩大已有限制时等待用户明确修改或同意。
- 范围配置须由服务端校验和应用编排持久化，不允许模型通过扩大 Tool 入参直接改写会话的用户限制。适配自然语言选择时仍遵守这一边界。
- 检索 Tool 可省略范围或显式进一步缩小范围。省略表示本次运行已经确定的范围；仅在会话范围为所有库时，才等于所有启用库。
- 向模型提供真实的启用知识库 ID、名称和说明目录，使其能选择存在的库；优先复用现有列表能力，不让模型猜 UUID。目录装配方式不要求新增独立的 Tool 平台。
- 检索服务、范围端口和 Qdrant 过滤一起支持选定集合，不能只修改 Tool 签名，也不能用移除过滤条件实现所有库查询。
- 全文 Tool 同样检查本次允许的知识库和当前可用状态。通过已知 `document_id`、旧工具结果或模型手写参数，均不能越过范围读取。
- 切换范围后，旧问答可继续展示，但新回答不得把范围外的旧工具结果、引用正文或摘要中的旧事实当成当前依据。当前范围配置必须独立于可被摘要压缩的自然语言指令保留。
- 本次知识库事实应以当前范围中重新取得并关联的证据为依据；模型上下文中的历史引用不能自动恢复为有效引用。通过运行上下文与引用校验共同落实，不仅写一句提示词。
- 全部停用、明确目标不存在、目录不可用和普通无命中分别处理。有限的重试与改写查询只能在允许范围内进行。
- 保留既有只读 Agent 循环、调用预算、截断提示与上游错误处理；Tool 名称、说明、默认提示词和空结果文案改为通用文档语义。

### 7. 证据与回答

- 证据是本次实际读取到的文档内容。引用关联至少能识别 `document_id`、KnowledgeBase、标题、取得时的 `content_hash` 及支持结论的片段；有 Source、URL、时间等信息时如实提供。
- 引用标识由应用根据实际 Tool 结果建立，供模型在答案中引用；前后端保留可校验的关系，不能从模型写出的任意 UUID、标题或外链反推它一定查过资料。
- 沿用当前消息与 Tool 结果承载必要结构化元数据，并贯穿流式响应和未压缩会话回放，不另存永久引用档案。面向模型的正文格式可以保持简洁，不要求模型阅读数据库版本实现细节。
- 答案中的知识库事实结论必须有关联证据。推断明确标注，并指出依据；不能用模型记忆填补资料空白后将其描述成资料中的事实。
- 资料不足时说明不足；已有资料相互冲突时列明出处与差异，不擅自把其中一项包装成确定答案。
- 服务端检查引用是否存在于当前允许的证据集合中。无效标识不得在页面上显示为已验证的可点击引用；修正失败时如实说明引用不可用，不补造出处。
- “引用存在”与“原文支持结论”分别验收。前者由程序确定检查，后者以代表问题和人工核对验证；不承诺仅靠引用校验就消除模型事实错误。
- 点击引用可看到实际命中片段与归属，并通过既有全文读取能力查看当前 Document。Chunk 序号不伪装成原文段落号或页码；仅在位置可靠且正文版本一致时定位，不强制引入永久段落身份体系。
- 新读取到的正文与检索片段版本不同时，区分各自的证据版本；旧 `content_hash` 不附到新正文上。过长正文沿用有界读取和明确截断，不把未读取部分当成不存在。
- `score` 继续是检索相似度，不显示成回答正确概率或证据可信度；同一内容的多个命中也不自动等同于多份独立佐证。

### 8. 实时原文与压缩后的回看

- 回看读取当时保存且仍在当前状态中的问答与 Tool 结果，不重新调用模型，也不重新查原文后改写旧回答。
- 查看引用全文时读取当前 Document。正文变化则提示“原文已更新”并展示当前内容，不保存或恢复整篇旧版本。
- 确认文档不存在时显示“原文档已删除”；网络、服务、登录或知识库停用错误显示各自状态，不统一伪装成删除。旧引用不可定位时也不能猜测原文位置。
- 保留既有会话压缩机制。早期原始问答被压缩后不再逐条回看，近期仍保留的消息继续展示；不得因为发生一次压缩就隐藏整个会话。
- 页面明确提示“较早消息已压缩，原始问答不再提供回看”。可折叠显示已有摘要作为背景，但摘要不作为可核验原文引用，也不能生成指向已压缩工具结果的恢复入口。
- 压缩按现有消息数量规则触发，不是按经过时间触发；一次提问可能包含多个模型和工具消息，短时间使用也可能发生压缩。
- 压缩生效后当前页面须在安全的运行收尾时与最新会话状态同步，避免刷新前可见全部旧问答、刷新后才突然消失；不打断正在进行的流式回答。
- 继续使用现有 checkpointer，不新增完整聊天副本、历史恢复 API 或永久证据快照。压缩引用元数据随所属消息退出可回放状态，不另行留档。
- 不提供回看不等于旧检查点已经物理删除。本阶段不新增检查点清理、按时间销毁承诺或逐 token 事件归档；删除会话沿用既有生命周期。
- 不承诺已经中断且尚未持久化的流式片段能够恢复为完整回答；回放不得把未完成回答伪装成完整结果。

### 9. 界面与工程衔接

- 普通检索、全文、文件管理、Agent 及设置中的通用入口使用知识库、文档和来源等既定说法。`news` 作为新闻 KnowledgeBase 的稳定业务键继续保留。
- 页面沿用现有导航、输入坞、检索流、管理分区和阅读器，不增加说明性落地页或独立文件管理产品。
- 前端仍只通过同域 `/api` 与 OpenAPI 契约访问后端；类型、错误映射、流式事件和历史回放同步更新。
- 复用现有应用组件与适配器边界，文件入口只新增所需导入与管理用例；不把数据库会话或基础设施客户端传入领域核心。
- 如果实际新增的 Payload 字段发生不兼容变化，按现有索引版本规则处理；仅增加知识库过滤集合不构成重建或清空数据的理由。
- 本次确定了用户行为与范围；字段命名、文件大小限制、分页参数和解析依赖版本等工程参数在实施时按现有约定集中定义并回填本文，不作为额外产品访谈前置。

## 测试决策

### 验证入口与原则

- 以既有 HTTP 应用入口为主要验证层，通过上传、列表、替换、查询、全文、Agent 流式输出及历史回放观察业务结果。浏览器验证复用同一条链路，不另造仅供测试使用的业务入口。
- 沿用已有多 KnowledgeBase 范围、Document 幂等与 revision、真实隔离 PostgreSQL/Qdrant、Agent Tool、SSE 与回放、检索流和安全 Markdown 渲染的测试先例。
- 外部模型与 Embedding 在确定性行为测试中使用既有替身；范围过滤、写协调与跨存储删除用隔离真实资源验证。最终另做必要的真实模型与浏览器验收，明确记录未运行和门控跳过项。
- 测试断言用户可观察结果、范围、版本和恢复行为，不固定私有方法名、内部调用次数、CSS 类或整段非契约文案。低影响展示改动不增加只复述实现的测试。

### 必须覆盖的行为

| 主题 | 主要验收场景 |
|---|---|
| 所有库与选择范围 | 至少两个启用库和一个停用库；默认所有、单库、多库、空选择、未知/停用目标、目录失败；停用库不进入实际过滤集合，无启用库时不请求 Embedding/Qdrant |
| 既有契约 | 旧 HTTP 缺省 news 和显式单库调用继续有效；冲突范围拒绝；默认搜索所有不扩大清理范围；既有 FreshRSS 与 Source 绑定规则不回归 |
| 上传与查看 | `.txt`、`.md` 成功入指定库；列表与当前正文可读；无 Source/URL/发布时间正常；UTF-8 BOM、空正文、无效编码、不支持格式与体积边界；Markdown 代码、表格文字、危险链接与原始 HTML |
| 新增与替换 | 同名新增保持独立；不同文件名替换仍保留目标 ID 和归属；完全相同替换无新 revision/索引；正文或可索引元数据改变触发更新；无效替换和并发冲突不破坏已有文档 |
| 索引与删除 | 保存成功但索引等待/失败不显示为可检索成功；重试不新增 Document；更新与索引交错只确认正确 revision；明确 ID 删除各处理状态文档；Qdrant 失败可恢复且不误报完成 |
| 会话范围 | 新会话默认所有；选定范围跨提问与重新打开保留；运行期间修改仅影响下次；Tool 缩小允许、越界拒绝；已知 ID 读取不能绕过范围；用户文本限定与页面范围一致呈现 |
| 范围切换与摘要 | 先用 A 库再切 B 库，仅存在于 A 的事实不能借旧消息或摘要成为 B 范围回答的证据；压缩不能丢失用户范围；资料不足不自动扩大 |
| 引用 | 每个有效引用可追到实际文档和片段；伪造标识、旧范围引用和文档版本混用被识别；流式与未压缩回放呈现一致；语义相似度不显示为事实置信度 |
| 实时全文 | 引用后替换原文，打开得到当前正文并提示更新；删除后明确提示；服务不可用、停用和删除不混淆；无法可靠定位时不高亮错误位置 |
| 会话压缩 | 用现有压缩机制产生摘要，当前页面与刷新后均只展示仍保留的近期问答；早期原始引用不可回看；摘要只作背景；中断与不完整工具结果如实呈现 |
| 权限与页面 | 普通账号不能上传/替换/删除或访问他人会话；既有检索与全文权限保持；桌面和手机上传、范围选择、文件列表、阅读与引用操作无内容遮挡或布局溢出 |

### 代表问题与消融

- 准备一组可重复的文本与 Markdown 样本，包含单库事实、跨库比较、无答案、资料冲突、文档更新、删除、无外部来源和较长文档中的命中。
- 为每个问题记录允许范围、应命中的 Document、支持结论的文本及允许的“不足”回答；记录实际引用与响应耗时。问题集覆盖上述场景即可，不为凑数量引入与本阶段无关的检索算法。
- 程序检查引用身份与范围，人工核对代表回答的事实支撑、推断标注和冲突说明。真实模型测试存在波动，如实报告结果，不用 mock 通过代替真实回答质量。
- 设计消融已移除关键词混合检索、重排序、完整会话归档、文档历史版本、文件自动合并及在线编辑，这些都不是已确认流程的必要前提。
- 实施收尾再逐项检查新增字段、适配器、兼容分支和测试是否保护实际需求。能用现有入口完成的流程不增加平行实现；简化后重跑受影响验证，不删除有效失败测试来制造通过。

## 超出范围

- PDF、Word、OCR、图片理解、音视频、压缩包、目录或批量导入、网页抓取及 Markdown 外链内容采集。
- 粘贴录入、在线正文编辑、独立标题编辑、富文本编辑器、原始附件字节下载与附件存储平台。
- 按文件名、正文 Hash 或语义相似度自动覆盖/合并文档，以及跨知识库去重、文档移动和 Source 历史重分类。
- 关键词与语义混合检索、重排序、新 Embedding 模型、知识图谱和查询规划平台。
- 完整会话档案、完整文档历史版本、已压缩问答恢复、永久证据副本和逐 token 流式事件回放。
- 新增检查点物理清理策略；不把消息压缩解释为数据销毁承诺。
- 账号对 KnowledgeBase 的细粒度权限、团队空间、审批、Agent 知识写入工具或新的服务拆分。
- 自动发布、恢复真实定时任务、迁移共享数据库、清空资料或重建线上索引。这些不是本次落实规格的授权动作。
