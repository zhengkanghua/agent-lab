# 02: 一次模型调用真的落进独立库

**要交付什么：** 独立的用量数据库与它自己那套迁移环境、只放一张用量表；接缝收到的登记被写进库（先同步直写，队列与批量留到 07）；每条记录带上账号、会话、运行三个引用和全部约定字段。做完能演示的事：问一次 Agent，用量库里出现一条与上游一致的记录，而业务库的迁移链完全不受影响。

**被谁阻塞：** 01

**状态：** 待开工

- [ ] 跑一次对话后，用量库里出现一条记录，输入／输出／合计三个 token 数与上游报的一致，缓存数按上游报的记，模型名、发生时刻、耗时、状态、用量来源齐全。
- [ ] 记录带账号、会话、运行三个引用；同一次运行里的多次模型调用引用同一个运行标识。
- [ ] 用量表的迁移与业务库各自独立：对业务库跑一次结构比对，不产生任何与用量表相关的变更；业务库里不存在这张表。
- [ ] 同一个调用标识重复受理不会在表里多出一行。
- [ ] 用量库的会话时区与时刻列的时区一致按 UTC 解释：写入一条记录后按 UTC 的日期边界查询，能查到它。
