# 05: 失败的、被取消的调用也留记录

**要交付什么：** 上游报错、超时、以及运行被取消这三种结束方式，各自留下一条记录：状态失败、token 为 0、用量来源缺失、耗时算到结束或取消那一刻。做完能演示的事：让模型报错一次、再让一次运行被取消，明细里各出现一条失败记录，而「停止」的行为跟今天一模一样。

**被谁阻塞：** 02

**状态：** 待开工

- [ ] 让模型客户端抛出上游错误，账本里出现一条状态失败的记录，token 为 0、用量来源缺失，账号与会话引用齐全。
- [ ] 让一次运行在模型调用进行中被取消，账本里出现一条状态失败的记录，耗时不超过取消发生的时间。
- [ ] 取消之后异常照旧向上传播：发起取消的一方仍然能观察到取消，运行的收尾与今天一致（不会被包装吞掉而变成「正常结束」）。
- [ ] 一次调用只产生一条记录：失败的那条不会在成功路径上再补一条。
