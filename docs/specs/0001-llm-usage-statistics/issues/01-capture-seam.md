# 01: 每次模型调用都经过采集点

**要交付什么：** 模型客户端外面多一层包装，由 Agent 运行时装配负责包住主模型与备用模型；采集点把「一次模型调用和它的用量」交给一个可从外面注入的采集器，缺省是空实现（什么都不记）。做完能演示的事：注入一个记录用的假采集器，跑一次带工具调用的对话（含重试），它收到的登记与这次运行里模型客户端被调用的实际次数一致，而逐字输出、工具调用与中间件行为跟今天完全一样。

**被谁阻塞：** 无（可立刻开工）

**状态：** 待开工

- [ ] 注入假采集器后跑一次含工具调用与重试的运行，登记次数等于这次运行里模型客户端被真实调用的次数（重试的每次尝试各算一次）。
- [ ] 走生产的流式入口跑一次对话，客户端仍然逐字收到分片，而不是等回答全部生成完才一次性收到。
- [ ] 包装之后模型仍然能调用检索工具：带工具装配跑一次，模型发出的工具调用被真正执行并返回结果。
- [ ] 不注入采集器时，装配不读用量库配置、不建任何连接，现有 Agent 的离线测试无需新增任何用量库环境变量即可全部通过。
- [ ] 包装不改变模型对外的可观测属性：把真实客户端包起来后，模型名、默认请求头、超时、温度、重试次数、能力画像与 provider 特有的构造参数都与未包装时一致。
