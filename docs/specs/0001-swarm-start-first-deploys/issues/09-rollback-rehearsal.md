# 09: 验收：版本回滚可用（演练 3）

**要交付什么：** 证明「一条命令切回上一版」是真的：切回后服务仍在、行为如旧，并且能证明跑的就是上一版代码——比对回滚前后服务定义里的镜像引用（含摘要）必须不同。若发现回滚回到的仍是同一个可变标签，就判定为触发「需要不可变标签方案」的停手线，另开规格，不在这里临时发明。

**被谁阻塞：** 06: 首次改造：停机一次把服务切上 Swarm（演练 1）

**状态：** 进行中（回滚与摘要比对已通过；浏览器里发一次新对话待确认）

- [x] 一条命令切回上一版后服务仍在、行为如旧（站点、搜索、对话、后台任务）
- [x] 回滚前后服务定义里的镜像引用（含摘要）确实不同——证明回到的是上一版；若没变，判定为触发「不可变标签方案」的停手线
- [ ] 回滚后仍能正常发起并完成一次新对话（图状态结构未变的前提下）
- [x] 记录了这次回滚能否成立的前提：上一版镜像仍在本地、这次迁移对旧版本安全

### 验收记录（2026-10-01 实测，服务器 `instance-20260723-1451`）

脚本 `output/swarm-09-rollback.sh`。回滚命令是一条循环（对三个服务各执行一次），走的是每个服务自己的
`PreviousSpec`（即上一次部署那份定义）：

```bash
for s in backend task-beat task-worker; do docker service update --rollback "agent-lab_$s"; done
```

**逐服务比对（只比整体差异会掩盖个别服务没换版本）**：

```text
回滚前：backend / task-beat / task-worker → backend-latest@sha256:26ea394008fb…
回滚后：backend / task-beat / task-worker → backend-latest@sha256:b315dee10c97…
三个都「✓ 与回滚前不同」 => 回到的是上一版那个具体镜像（不是同一个可变标签）
```

**服务与端点**：三个服务仍 `1/1`；`/ready=200`、`/health=200`；容器 Up（API `healthy`）。

**两个前提**：① 上一版镜像在本地（`docker images --filter dangling=true` 里能看到被顶替下来的
几版，如 `5d756f4e3a21`）；即使不在，也能按摘要从 ACR 拉回（摘要不可变）。② 这次迁移对旧版本
安全——本次部署只改了注释，CI 日志里两次 `alembic` 都只打了 context 行、没有 `Running upgrade`，
所以没有新迁移；表结构与图状态结构都没变，旧代码能接着跑。

**顺带验证了工作流新增的自动清理**：CI 那次部署替换下来的三个旧任务容器已经不在了（否则此刻应当
看到 6 个 `Exited`：CI 部署的 3 个 + 回滚脚本的 3 个），实际只剩回滚脚本自己换下的 3 个——说明
工作流里那一步生效；手动清理命令（也已写进手册）：
`docker ps -a --filter name=agent-lab_ --filter status=exited --format '{{.Names}}' | xargs -r docker rm`。
