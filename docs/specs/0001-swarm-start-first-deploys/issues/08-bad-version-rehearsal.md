# 08: 验收：坏版本不接班（演练 4a、4b）

**要交付什么：** 两种坏法各测一次，看的是同一件事——好版本会不会被坏版本替掉。4a：新版本启动期就失败（容器退出），期望旧任务不被停、更新自己回滚、用户无感。4b：新版本起来了但就绪检查一直不过（进程不退），记录旧任务是否被停、以及那个不健康的新任务是否在收流量。这一条同时是停手线的落点。

**被谁阻塞：** 06: 首次改造：停机一次把服务切上 Swarm（演练 1）

**状态：** 已完成（4a / 4b 都已实测；判定：按现规格继续）

- [x] 4a：新版本启动期失败后，旧任务仍在服务（有存活证据），更新自己回滚，用户侧无感
- [x] 4b：记录了旧任务是否被停——未被停则本工单通过；被停则判定为触发停手线
- [x] 4b：记录了那个不健康的新任务是否在收流量
- [x] 结论明确写成「按现规格继续」或「停在这里、另开一份规格补代理（自己拿指针、只把流量发给已就绪的容器）」

### 验收记录（2026-10-01 实测，服务器 `instance-20260723-1451`）

脚本 `output/swarm-08-bad-version.sh`（另有一次 4b 重测）。全程有后台小负载每秒打一次 `/health`：
**400 次请求、非 200 共 0 次**（最慢 98ms）——包括 4a 的回滚与 4b 那次真的滚动更新。

**4a（启动期就失败）**：把 `DATABASE_URL` 改成连不上的地址（服务定义里确认只剩 1 条，即坏值真的生效）。

```text
更新器结论：{"State":"rollback_completed", "Message":"rollback completed"}
旧任务容器 onratpwcao…：Up 9 minutes (healthy)          ← 全程未被停
失败任务日志：ERROR: Application startup failed. Exiting.
              Child process [8] failed to start, stopping the parent process.
站点：/health=200
```

**4b（起来了但就绪一直不过）**：第一轮把 `LLM_MODEL` 改成 `auto` **没有测成**，因为**这台上游把
`auto` 列在 `/models` 里**（它是中转站的路由开关，但确实在列表里），所以「配置的模型不在上游
列表里」这个判据抓不到它：新任务 /ready 一直 200、被判健康、更新正常完成（`State: completed`）。
**顺带记录**：那个任务收到 207 次 ingress 请求并不矛盾——它的 /ready 是 200，它就是健康的；
代码注释里「auto 之类的路由开关不是模型名」这句話对这台上游不成立，属于后续单独处理的产品侧
事实，不在本规格范围。

第二轮换成一个真正不在列表里的名字，结果全部符合预期：

```text
更新器结论：{"State":"rollback_completed", "Message":"rollback completed"}
坏任务 l4hnharck…：GET /ready → 503 × 4
                   来自 ingress(10.88.*) 请求数 = 0      ← 未就绪的任务一个请求都没收到
旧任务 qglbb00r…：Up 12 minutes (healthy)                ← 全程未被停
                   142 次 /ready 200、94 次 ingress 请求——旧版本照旧服务
```

**判定：按现规格继续。** 两条停手线都不成立：旧任务在两种坏法下都没有被停，而且未就绪的新任务
确实收不到流量（4b 第二轮：0 次 ingress 请求）。就绪端点在这两种失败下也都如实报了未就绪
（4b 是 503，4a 是进程直接退出）。

**顺带两条工程事实**：① 规格里 4b 写的「进程不退」在本系统里不成立——`/ready` 一直不过的任务会
被 agent 杀掉（工单 01 的 C3 已实测），所以 4b 实际走的是「未就绪 → 无流量 → 被杀 → 回滚」这条链；
本工单按可观察结果验收，不按那条字面描述。② `--env-rm 键 --env-add 键=坏值` 能可靠覆盖 `env_file`
注入的那一份（两轮都在服务定义里确认过只剩 1 条），这是个好用的演练手法；演练结束后重新应用
`docker-stack.next.yml` 就把服务定义恢复成唯一真源（实测：恢复后 `/ready`/`/health` 均 200）。
