## 什么该写成一篇

判断标准一条：**这件事的完整过程，是不是必须同时打开三个以上不同目录的文件才能看明白？**

是就写，不是就不写。单个模块内部的顺序写在它自己的 docstring 里，不要搬过来。

已经判为不需要的：用户管理（一条直线，看 `api/user_admin.py` 就够）、读取单篇文档（一次调用）。

## 写什么、不写什么

写：跨模块的顺序、模块之间的接缝、终态有哪几种、失败时停在哪、以及**为什么这么切分**。

不写：

- SQL、枚举值、阈值、单个模块内的算法。唯一真相在代码里，抄一份就是埋雷。
- 逐行的函数调用清单。那是代码的工作，而且一重构就全错。
- 能力做什么。那是 `README.md` 的工作。

判断某句话该不该留，问一句：**这个模块重构之后，这句话会不会变成错的？** 会，就说明它写细了。
