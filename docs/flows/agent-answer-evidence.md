# Agent 的运行范围、证据引用与回看

页面保存当前会话的 KnowledgeBase 选择。发送前，后端先校验会话归属，再解析启用目录并冻结本次范围；新会话默认所有启用库，旧会话迁移保留 news。SSE 的 `run_started` 将会话 ID、运行 ID 和实际范围交给页面。运行期间保存的新选择只影响下一次提问。

主模型接收当前问题、保留的历史问题和本次 Tool 结果；旧答案、旧 Tool 和摘要仍可在近期回看中展示，但不能进入新运行充当证据。`search_documents` 可按用户要求缩小范围，`read_document` 同时核验允许范围和知识库启用状态；已知 Document ID 不能越界。资料不足时不能自动扩大页面选择。

工具与普通检索、全文共用已采用版本的可见性规则：新候选准备期间旧版本仍可用，拒绝或删除后停止后续取用。管理页保留的历史和原件不通过 Agent 工具开放。

Tool 返回实际读到的片段及应用分配的引用标识，证据关系随消息写入 checkpoint。模型引用这些标识作答。结束时，服务端从持久状态得到最终答案、完成状态、有效与无效引用，作为 Done 返回；前端校正临时 token，并同步最新保留的问答。回放使用同一套关联规则，工具调用仅在所属问答内配对。

一次运行由服务端自己驱动，不挂在浏览器连接上：请求受理后由后台驱动者把事件流读到结束并收尾，SSE 响应只是它的一个订阅者。关页面、断网、切走会话都只减少订阅者，运行照旧跑完并落进历史；要真的停下它，走 `POST /agent/stop`（带会话 id 与运行 id，幂等）。同一个会话同时只允许一次运行，再来一次返回 409 `agent_run_in_progress`（界面据此说「正在生成」，不引导重发）。刷新页面时如果上一轮还在跑，回放响应里的 `active_run_id` 让界面显示「正在生成」、禁用发送，并每隔几秒重读历史直到服务端不再上报——前端不设放弃上限，因为失活判定会结束服务端的上报。删除一个正在运行的会话时先请求停下它并等它释放占位，再清历史、再删归属，避免运行在历史清空之后继续写回。

用户点击行内引用或引用列表，阅读器显示当时取得的片段，再单独请求当前全文。原文变化时同时保留旧依据和新内容；删除、停用、服务不可用分别提示。无法从索引文本可靠映射到 Markdown 原文时不猜测高亮。原始 Cosine score 只表示检索相似度。

| 失败或生命周期边界 | 用户看到 |
| --- | --- |
| 目录加载失败、空选或目标失效 | 提问前失败，不退化为无过滤搜索 |
| Tool 试图越界 | 明确失败，不能凭已知 ID 绕过范围 |
| 模型生成未知或旧运行引用 | 引用无法核验提示，不提供伪造阅读入口 |
| 上游重试产生临时文字 | Done 用已保存答案校正，回看与终态一致 |
| 达到模型预算、上游截断或流中断 | 已有内容留在会话里，状态如实标成未完成；界面不加结局标签 |
| 浏览器断开（关页面、断网、切会话） | 运行不受影响，照旧跑完并落进历史 |
| 用户点停止 / 上游失败 / 超时 | 运行收尾，已推出去但未落库的那段文本补写进会话，状态标成未完成 |
| 刷新后这一轮还在跑 | 显示「正在生成」、发送键不可用，等到服务端不再上报后自动换成最终内容 |
| 删除正在运行的会话 | 先请求停止并等它释放占位（上限 10 秒），再清历史、再删归属 |
| 部署时上一轮还在跑 | 旧进程会把这条连接上的运行跑完再退出（uvicorn 默认无限等连接），所以通常既不中断也不用等解锁；只有一次运行超过 360 秒的停止宽限、或进程被强杀（崩溃、OOM）才会丢掉它，那时在途标记只能等失活判定（约 2 分钟）释放，窗口内界面显示「正在生成」、发送键不可用 |
| 结束后历史同步失败 | 保留本次页面内容并提供同步重试 |
| 较早问答被压缩 | 当前页和刷新后均只保留近期原始问答；摘要标作背景 |

**被中断的那一次运行不会自己恢复，这是本期明确不做的。** 要恢复就得把运行搬进任务队列（连图、模型客户端和 checkpointer 一起搬进 Worker，事件跨进程传递），规格把它列在超出范围；崩掉之后能做的只是「让这个会话能重新提问」，不是「接着把那次运行跑完」。

**硬杀留下的在途标记是已知边界，不掩盖。** 进程被强杀（崩溃、OOM、超过停止宽限）时没有任何清理动作会执行，在途标记只能等失活判定自动释放。这不是可以修掉的缺陷，而是「无法区分进程已死与运行很慢」的必然结果——不要为它加快速失活检测，也**不要**在进程启动时把在途标记一律清掉：`WORKER_COUNT` 大于 1、以后还可能有滚动部署，启动时清标记无法区分「那个进程死了」与「那个进程还在另一个进程里跑」，会把活着的占位抹掉，于是两次运行同时写一个会话的历史（静默覆盖）。真要缩短这段窗口，应改的是续期间隔与失活阈值这两个常量（代价是更频繁的活跃时间写入、以及更短的事件循环卡顿容忍度），不是加一条「谁有权清标记」的规则。删除正在运行且等待窗口内没停下来的会话另有一条已确认的代价：那次运行随后仍可能把收尾内容写回，留下一条查不到也删不掉的孤儿会话，靠运维命令清理。

压缩只在新提问开始时执行，保留完整近期问答，不切断正在使用的证据链。退出可回看状态不等于旧 checkpoint 已物理清除，也不提供独立完整档案。设计取舍见 [ADR 0021](../adr/0021-agent-run-evidence-and-replay.md)；跨层验证见 `backend/tests/test_agent_evidence_scope.py`、`backend/tests/test_agent_runs.py`（运行生命周期与停止）和 `frontend/src/pages/AgentChatPage.spec.ts`。
