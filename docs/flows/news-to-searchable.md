# 新闻从 FreshRSS 到可被检索

FreshRSS 接收与后台处理分开：同步把选定的原始 HTML 保存到 MinIO/S3，并在 PostgreSQL 确认处理待办、来源位置和必要的文档批次受理；后台再生成结构、Chunk 和候选索引，成功采用后才对检索开放。两个阶段不共享长事务。HTTP Pipeline 先返回受理编号，由 Worker 顺序执行一次接收和处理批次，最终统计通过任务执行详情读取；CLI `run-once` 保持直接执行。文档剩余待办通过持久批次交接继续推进。

## 接收与来源位置

先按允许分类发现 Source，新来源只登记；绑定启用 KnowledgeBase 后才拉取文章。首次同步保存最近的有界基线，之后从已提交位置继续追赶；不保证重新导入全部历史新闻。

适配器按协议选择一份正文，不拼接 content 和 summary，不回源抓取页面。应用先保存接收意图，再在数据库事务外写入并核对原件；最后锁定来源及知识库复核准入，同一事务确认待办、checkpoint 和必要任务受理。重复资料保持幂等，索引元数据变化仍可产生新候选。

已可靠接收的单篇解析异常不会阻塞同页正常资料。原件未保存或来源确认失败时不能推进 checkpoint，已存在的接收依据供下一次核对复用；其他来源已提交的数据保留。checkpoint 表示此前资料已可靠接收，不表示全部已经采用。

## 处理、审核与正式使用

文件和 FreshRSS 共用结构化处理能力。HTML 首段、标题和内容块保留阅读顺序，确定性规范化在结构转换后执行；异常留待人工，其余自动采用。解析和网络 I/O 不占用长数据库事务，迟到计算结果不能覆盖较新候选。

新索引依据冻结预览准备并核验，成功后切换正式版本，失败时旧已采用版本继续可用。人工草稿与最新来源分别保存；人工修正过的资料收到更新后等待复核，来源不能覆盖人工正文。审核、拒绝、历史与完整删除共用 [文档生命周期](file-document-lifecycle.md)。

## 恢复边界

纯计算领取可以在确认条件满足后重新排队；明确失败、待审核和拒绝记录等待人工处理，不能靠每次 cron 自动恢复使用。远端写入结果不确定时仍由持久写协调阻挡，先确认旧进程和未决写入已停止，再按失败阶段恢复。

删除待办阻止同步和采用重新写入目标；接收遇到删除目标不能越过未保存的来源内容。兼容全量重建仅使用已采用版本的冻结 Chunk 清单，准备成功后发布新 generation，不重新解析或改变历史预览。清理及任务恢复见 [定时任务执行](scheduled-job-execution.md)。
