# 从会话选择模型到一次调用打到哪个上游

这条链路回答一件事：用户在会话里挑的那个模型，一路走到「这一次调用实际用了哪个上游、哪个模型名」。

## 谁负责哪一段

| 位置 | 负责 |
| --- | --- |
| `features/agent-chat/` 的选择器 | 每次打开重拉目录（`GET /llm-models/available`，任何登录账号可读）；改选即保存；当前选择指向已停用或不存在的条目时显示失效态与重选入口 |
| `api/agent_threads.py` | `PATCH /agent/threads/{thread_id}/model` 把选择写回会话行；**不看运行中、不碰停止请求**（运行中改选照样保存） |
| `api/agent_chat.py` | **开始运行之前**解析当轮生效的那一份：请求里给了就用请求的，没给才用会话里存的，都没有就用默认 |
| `services/llm_model_selection_service.py` | 解析本身：直读目录表判可用性（**不经客户端缓存**），产出 id + 展示名 + 上下文窗口的快照 |
| `agent/streaming.py` | 把这份快照**冻结**进提问消息的 `agent_run`，同时放进运行上下文 |
| `agent/model_resolution.py` | 到了模型调用那一刻，按运行上下文里那份快照解析出客户端（按 id 读目录 + 60 秒缓存） |
| `agent/runtime.py` | 装配期把解析包装包在用量采集**里层**，塞进图 |
| `agent/runs.py` | 接手一条被排空的运行时，从提问消息的**冻结快照**重建上下文，不回查目录 |
| `main.py` | 应用级异常处理：模型目录的领域错误带上它自己的状态码、`code` 与文案 |

## 顺序

1. **选择**：选择器一改就调保存接口写进会话行的「当前选择的模型」列；提问请求体里带的那份也写回同一列。即「改了就是记住」，**没有「只对这一次」的单次覆盖**。**保存时不判可用性**——否则同一个失效选择会从保存与提问两处各拿到一条不一样的提示。
2. **提问**：`POST /agent/chat` 在归属校验之后、建运行之前解析当轮生效的那一份，并只校验这一份（另一份失效不影响这一轮）。
3. **冻结**：解析结果连**展示名与上下文窗口**一起写进提问消息，与知识库范围快照同一个口袋；范围与模型是两样东西（范围约束工具能取到什么，模型决定谁来回答）。
4. **调用**：装配期那个解析包装每次调用时取当轮条目 → 读目录 → 拿客户端（或复用缓存里那个）→ 转交。**它的外面包着用量采集**，所以一次调用恰好一条记录、`model_name` 是上游模型名。
5. **排空与接手**：接手方从冻结快照重建，**不重判可用性**——那一轮的用户是带着那个模型开始的，接管是平台内部的事，不在中途给他换。

## 终态与失败边界

| 情形 | 表现 |
| --- | --- |
| 请求给的 id 在目录里不存在 | **开始运行之前** 404 `llm_model_entry_not_found`，模型一次都没被调用 |
| 生效的那一个已停用（含所属渠道停用） | 同前，409 `llm_model_unavailable`；与上一条**共用同一句面向用户的文案**（换一个模型） |
| 目录为空或全部停用 | 409 `no_available_llm_models`，文案指向超级用户（用户没法自救） |
| 会话里存着失效的选择 | **照样保存成功**；下次提问在解析那道门被拒 |
| 条目在运行途中被停用 | 接手仍用它跑完（快照冻结着）；要停就停整个会话，或让上游自己失败 |
| 条目后来改名或停用 | 已发生的那几轮显示**当时的名字**（展示名也是快照，回放逐轮读出） |
| 目录读不到（前端） | **不判失效**：读不到目录不等于「你选的那个不能用」，只显示加载失败 |
| 解析不出客户端（不变量被破坏） | `RunModelUnresolvedError` → `agent_internal_error`（500）＋ 日志指出哪一次运行；**不给它单开面向用户的文案** |

## 为什么这么切分

- **为什么按调用期取窗口、不按模型 id 回查目录。** 目录随时可能被改；回查会在「运行已排空、被别的进程接手」时给出与冻结那一轮不同的值。窗口与展示名一样，属于「那一轮的事实」，冻结下来才自洽。
- **为什么可用性判定不走客户端缓存。** 那道门直读目录表，所以刚停用的模型**立刻**不能被选中，不必等缓存过期；而解析那一层**故意不重判可用性**，接手在途运行才能用已停用的模型跑完。
- **为什么「只是被停用」不重建客户端。** 停用只是「不再被新的选择解析到」；接手那条路仍然要用同一个客户端，重建只会白丢一套连接池。判断要不要重建比的是地址、接入类型、凭据密文、上游模型名与上下文窗口这五项。
- **为什么装配期那个包装不读环境变量、不发请求。** 模型配置的唯一事实源是目录表；装配期不碰它，目录为空时进程照样起得来，只有第一次提问才会以明确的错误码暴露。

失败与缓存的取舍见 [ADR 0046](../adr/0046-model-catalog-and-user-model-choice.md)；这条链路与回答、证据的关系见 [Agent 运行范围与证据引用](agent-answer-evidence.md)。
