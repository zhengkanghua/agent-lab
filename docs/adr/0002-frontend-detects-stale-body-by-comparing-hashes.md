# 正文过期由前端比对两个 content_hash 判定

检索结果带的 `content_hash` 是 Qdrant 已索引的版本，全文详情带的是 PostgreSQL 当前的版本，两者不等即表示正文在被索引之后又改过。判定放在前端，由消费方自己比对；后端不判过期、不返回过期标志、也不拒绝返回过期结果。

后端不加标志位，是因为检索路径是纯 Qdrant 读取、不碰 PostgreSQL，加标志位等于让每条检索结果回查一次库，破掉那条边界换来的只是把一次比较从前端搬到后端。不拒绝返回，是因为刚更新过正文的资料在索引跟上之前会彻底搜不到，用户分不清是没有这篇还是索引在追；给出旧版本并明确提示比静默少给更可用。

## Consequences

判定责任在消费方：每个要打开全文的入口都得比一遍，漏掉不会报错，只会安静地不提示，用户看着旧正文以为是最新的。现有入口都走 `useDocumentReader` 的同一处实现，新入口要么复用、要么再实现一遍。
