# 全局业务配置入库，与个人偏好分开管理

2026-09-09，老板确认把已有后端管理能力接入前端后台，并将日常业务选择从部署配置逐步迁入 PostgreSQL。此次需求访谈的 Q1 至 Q7 已确定 FreshRSS 管理范围、全局字典权限、多模型服务连接和配置留痕方向；其余交互与生效细节继续访谈，业务代码尚未实施。

## 已确认的决策

- FreshRSS 订阅维护纳入本项目后台，包括新增订阅、修改订阅名称和分类、取消订阅；本期管理现有的一套 FreshRSS 连接，不扩展为多个实例或账号。
- 来源目录、RSS 同步分类白名单、单个 Source 同步启停、KnowledgeBase 绑定及状态展示纳入管理能力。分类白名单可以配置，并作为统一准入条件；Source 的独立开关不能绕过白名单，已有 KnowledgeBase 启用和归属要求继续有效。
- 支持多个生成式模型服务连接，供 Agent 主模型和备用模型选择。该决策不改变 Embedding 模型、向量维度或索引规格。
- 新增字典类型表与字典项表，允许超级用户在后台自由创建字典类型和字典项。新建字典只建立数据目录，业务页面或执行逻辑使用它仍需开发接入，不根据任意字典项自动增加任务类型、解析格式或模型接入协议。
- 全局字典和全局业务配置共同作用于全站，只有超级用户可以创建和修改；个人偏好独立管理。个人明确保存的默认值只在相应功能允许覆盖的范围内优先，不得修改全局字典、扩大可选集合或绕过全局业务规则。
- 管理对象保留创建人、创建时间、修改人、修改时间，并记录修改前后值。本期不增加恢复历史配置的操作；记录粒度、留存和敏感字段表达方式继续细化。

## 取舍与边界

允许自由创建字典类型，满足后台统一维护选项目录的需求；代价是某些字典可能暂时没有业务消费方。后台需要区分数据已经保存与功能已经接入，不能把新增字典项显示为后端已经具备相应执行能力。

全局管理与个人默认值分开，使修改字典和业务规则始终具有明确的管理权限。此决策保留 [ADR 0018](0018-settings-hub-with-local-preferences.md) 中个人设置与后台管理的分工，不把个人偏好混入全局字典；具体默认值的组合方式随对应配置用例细化。

本条原有一句「也不据此迁移个人偏好到账号级存储」，**已由 [ADR 0027](0027-user-level-preferences-in-database.md) 取代**：个人偏好现已迁入账号级表 `user_preferences`。取代的触发条件是提示词的消费方从客户端转移到了服务端，与本条要防的事情无关——本条真正要防的是「个人偏好污染全局字典、扩大可选集合或绕过全局业务规则」，这个原则继续有效。个人偏好与全局字典仍然是两套东西，不合并。

FreshRSS 订阅维护属于对外写入，订阅变更与本项目已接收 Document 的生命周期需要分别表达。取消订阅后是否保留已有资料、暂停期间如何续接、远端操作结果不确定时如何呈现，尚未在本轮决定；本 ADR 不把订阅维护授权解释为已经执行任何真实服务操作。

模型服务连接与实际选用的模型需要独立于普通字典表达；凭据保存、模型可用性验证和生效方式尚待确认。存入数据库本身不保证各 API worker、scheduler 或 Agent 运行中的配置自动更新。

已有任务 cron、参数、KnowledgeBase 和 Source 记录继续由各自业务表承载，不因引入字典而复制为第二份事实来源。原始资料、人工审核与已采用版本的设计仍以 [ADR 0022](0022-pluggable-document-processing.md) 和 [ADR 0023](0023-durable-intake-and-document-review.md) 为准，本次管理配置方向不改变其已确认规则。
