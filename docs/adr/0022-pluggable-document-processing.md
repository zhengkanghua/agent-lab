# 文件与 FreshRSS 共用可替换的文档处理组件

原有 Markdown 提取流程把标题和内容块压平成文本再复用通用切分器，无法保证每个 Chunk 保留章节上下文。老板确认接入 Docling 作为首个结构化处理实现，文件上传与 FreshRSS 共用同一个后端内部的文档处理组件：入口只负责接入和归属，解析、结构切分、向量化各自通过项目自己的契约提供能力，Docling 的数据类型和 SDK 调用限制在适配器内部，预览和采用使用同一份冻结的 Chunk 清单。原始上传文件和 FreshRSS 原始 HTML 用 MinIO/S3 私有对象存储保留，以便核对原件和用新规则重新处理。不实现旧正文迁移或新旧流程并存，切换时清空开发资料后重新导入。本期文件上传仍只开放 MD 和 TXT，组件边界允许后续加 PDF、Word 等输入适配器，但不提前实现。

用「组件 + 契约」而不是两套流程，是为了避免两条入口分别维护解析和切分规则，并让 Docling 的升级或替换不扩散到接入、业务存储和检索调用方。代价是要维护一层实现映射；原件留存增加了对象存储依赖与生命周期协调成本，换来可核对、可重新解析的输入依据。接收、审核与版本切换的规则见 [0023](0023-durable-intake-and-document-review.md)。
