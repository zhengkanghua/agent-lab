# 文件与 FreshRSS 共用可替换的文档处理组件

2026-09-08，原有 Markdown 提取流程把标题和内容块压平成文本，再复用通用切分器，无法保证每个 Chunk 保留章节上下文。老板确认接入 Docling，同时要求处理实现可替换、职责集中，并让文件上传和 FreshRSS 共用处理能力。2026-09-11，该决策已落入代码；实际存储验收与环境切换仍需独立完成。

## 已确认的决策

- 本期文件上传仍只开放 MD 和 TXT，不新增 PDF、Word、Excel、PPT 或图片上传。FreshRSS 已有的 HTML 正文也进入统一处理，但不因此开放 HTML 文件上传。
- 在后端内部建立共同的文档处理组件，文件与 FreshRSS 入口负责接入和归属，组件承担结构化解析与 Chunk 产出；Docling 是首个处理实现。
- 解析、Chunk 切分和向量化各自通过项目自己的契约提供能力，Docling 的数据类型和 SDK 调用限制在适配器内部。组件入口集中表达输入、输出和错误语义，让内部算法或实现变化尽量不影响调用方；公开契约需要调整时再评估调用方变更。
- 以项目结构化结果替代旧的字符串 `ChunkPipeline`，解析、结构切分、向量化和索引准备各有独立端口，由装配选择实现。预览和采用使用同一份冻结 Chunk 清单，向量化只消费已确定的文本；索引规格来自独立契约。旧 Builder、递归切分器及其专属索引服务已移除，当前方法名、签名不是必须保留的验收要求。
- 组件边界应允许后续增加 PDF、Word 等输入适配器，并复用后续处理能力；本期不提前实现这些格式的解析或上传入口。
- 原始上传文件和解析正文分别保留，并提供原始文件下载，以便核对原件和使用新的解析规则重新处理。
- 本期使用 MinIO/S3 私有对象存储保存原始上传文件和 FreshRSS 原始 HTML，由后端通过项目自己的对象存储契约读写；PostgreSQL 管理文档归属、对象引用、处理状态、版本关系和审核记录。对象存储配置由部署环境提供。
- 当前处于开发阶段，老板确认现有资料可以清空后重新导入，本期不实现旧正文迁移或新旧处理流程并存。清空属于切换时的资料重置，本记录不表示该操作已经执行。

## 取舍

延续 [ADR 0020](0020-knowledge-base-management-slice.md) 的后端内部组件与适配器组织方式，把结构处理能力用于文件和 FreshRSS，避免两条入口分别维护解析和切分规则。保留独立契约需要维护实现映射，但可以让 Docling 的升级或替换不扩散到接入、业务存储和检索调用方。原件留存增加了对象存储依赖与生命周期协调成本，换来可核对、可重新解析的输入依据；私有存储的读取继续受后端文档权限约束。

原始资料持久接收、后台处理、人工审核、已采用版本保留与删除清理的规则见 [ADR 0023](0023-durable-intake-and-document-review.md)。具体组件契约与表结构由助手根据这些已确认语义收敛，不把当前实现签名或固定新增表数作为前提。
