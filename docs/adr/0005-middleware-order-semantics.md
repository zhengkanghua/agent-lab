# 中间件顺序的语义：越靠后越内层

`create_agent(middleware=[...])` 列表里越靠后的中间件越内层、越先执行，所以重试类中间件必须排在兜底类之后：反过来兜底会在内层先把异常吞掉，外层的重试永远收不到异常、静静地不工作。这与「读起来的顺序就是执行顺序」的直觉相反，而且写出来的代码看着完全正确，只断言「失败时返回了安全文案」的测试在两种顺序下都会通过，所以必须写下来。两侧都实测过：重试排在兜底前面时工具只被调用一次、重试完全没发生，排在后面时被调用「首次加重试次数」那么多次。当前组装顺序以 `agent/middleware.py` 为真源。

配套一条约束，缺了顺序也白排：重试中间件的 `on_failure` 必须显式写 `"error"`，默认值 `"continue"` 会让它自己造一条消息返回，异常同样到不了外层兜底。

## Consequences

针对这类中间件的测试必须断言底层被调用的次数，不能只断言最终文案。升级 `langchain` 时这条语义要重新验证：它是框架的组装行为，上游改了我们不会收到编译错误。
