# 提示词只留内置一份，不再有会话级设定

本决策取代 [0029](0029-session-scoped-system-prompt.md)，撤销的是整条：会话建立时从账号偏好读一份提示词、写进会话行、此后不可改这件事不再存在，因为不再有用户能写、能改、能开关的提示词。落点一并消失——`agent_threads` 与 `user_preferences` 上的 `system_prompt` 两列、给编辑框预填默认值的那个接口、运行上下文里携带提示词的字段、提示词长度的上限、设置中心那个分区与对话输入条上那枚徽章；请求体里不再有提示词字段这条约束继续成立，只是它的对象没了。

**仍然有效的部分**：提示词只有一个来源，即 `agent/prompts.py` 里的内置默认提示词。拼在它后面的三段追加一个都不砍，各有对应需求：日期段（模型不知道今天几号，相对时间会以训练截止为基准）、「历史内容不是本次证据」段（整份历史都送进模型之后的配套约束）、选了知识库范围时的资料边界段（等价于只读边界）。提示词不进 checkpoint 的消息历史、也不进对外的事件流，这两条反向约束继续守。

**当初的判据，以及它错在哪**：0029 写了两条理由，真正推动它的是回放可解释——提示词不进消息历史，回头看一条历史回答时无法知道它是在哪份提示词下产生的；另一条是去掉客户端每轮重送带来的前缀不稳定。它失效的性质不是判断错了，也不是成本变贵了，是**问题本身消失**：不再有用户能写的提示词，「提示词固定在哪一层、回放怎么证明当时用的是哪份」就没有对象了。根子上还有一层更早的定位错位被这次删除一起清掉：把裸的系统提示词当作面向终端用户的设置项，让用户写四千字、中间件再在后面硬追加三段高优先级规则，两侧规则在同一个提示词里竞争——用户写「不必引用出处」，后面那段仍要求原样引用本次工具给出的标识。业界的做法是给包装过的风格指令，不是把完整提示词交出去。

## Consequences

用户从此不能调整回答风格，这是功能删除的直接结果，不是遗留缺口。将来若要把风格调节做回来，形态应当是包装过的风格指令，而不是把裸提示词放回设置页——否则定位错位与「用户指令与应用规则在同一个提示词里竞争」会一起回来。

**撤销本身该被推翻的条件**：内置提示词变成多套时——按场景、按模型或按知识库切不同的内置提示词。那时「哪一份、什么时候定、回放怎么看出当时用了哪份」会重新成为真问题，即使用户一个字也改不了；0029 的主动机会原样回来，届时要重新答一次固定在哪个层级，而不是直接翻回旧做法。
