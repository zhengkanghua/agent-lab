# 主模型接收会话的完整历史，证据隔离只由证据层承担

同一会话允许切换 KnowledgeBase 范围，[0021](0021-agent-run-evidence-and-replay.md) 因此把送给主模型的历史裁成「只保留用户提问」——历史回答、历史 Tool 内容和历史摘要一律不送。这次撤销那条裁剪：**主模型接收 checkpoint 里的整份上下文记录**，四样都送。

理由是范围与对话正交。**本次运行的知识库范围是 Tool 的参数**：它决定工具能取到什么、哪份 Tool 结果算本次可核验的证据，不决定模型能说什么。前几轮用了 ABC 三个库、这轮只用 A、B，两者不冲突——模型可以拿历史和新查到的内容一起回答。范围那份记录继续冻结在每轮提问的消息上（证据核验与续跑都读它），只是不再用来裁剪消息。

0021 真正要防的是「新回答拿旧范围的事实作答」，而那条的硬保证在**证据层**：`tool_evidence()` 只承认本次运行、允许范围内的成功结果，旧的 `[[E...]]` 在新运行里一定核验不出来。裁剪能额外压住的只有「模型不重新检索、直接复述旧结论」——那是通用的偷懒问题，范围一直不变的多轮会话里同样存在，业界的做法是要求事实性结论必须来自本次检索，不是删历史。裁剪之前，模型对同一会话此前的往来没有任何记忆，而这份代价一直在付。

**送给模型的那一份要把旧引用标记剥掉**（`[[E1a2]]` 变成 `[出处已失效]`），因为模型会照抄旧标识，抄进新回答就是一批解析不出来的非法引用。剥的只是发送副本，checkpoint 里的原文不动，用户回看时当年的引用仍然点得开。

**0021 里继续生效的部分照旧**：每次运行冻结实际范围，会话知识库选择独立保存在归属表，运行中的改选留给下一次；引用标识由应用为实际 Tool 结果分配，随同一条消息保存归属与 `content_hash`，流式收尾与历史回放共用同一套证据核验——程序确认的是出处身份，不把它解释为模型结论已获事实认证；临时 token 可能来自上游重试，不能直接作为持久答案，最终文字、完成状态和引用一律从 checkpoint 取得，预算耗尽、上游截断和未持久化的中断不伪装为完整回答。

历史压缩改用**模型窗口占比**而非消息条数：触发取窗口的 80%，压缩后保留 30%。压缩触发后先按「换内容、不删消息」清掉较旧的 Tool 结果正文（`tool_calls` 与 `ToolMessage` 成对是上游接口的硬要求，只能换 `content`、不能删消息），清完重新计量，够用就不调摘要模型。摘要随后作为历史的一部分送给模型——它从此是模型对被压缩那一段的唯一记忆，所以摘要模型的输入不再截断。窗口值按每次调用读取而非烤死在进程启动，为「模型将按会话可变」留出位置。

## Considered Options

**维持 0021 的裁剪。** 界面与模型所见严格一致，模型不可能复述旧范围的事实。代价是模型对上一轮自己答过什么一无所知，而绝大多数会话从不换范围——这是最常见的情形在替最罕见的情形付账。否决。

**按「旧范围 ⊆ 本次范围」筛。** 范围不变或放宽时送全量历史，收窄或换库时只送提问；每轮范围本来就冻结在提问消息上，成本接近零。判据比实际需要粗：放宽时旧事实仍在新范围内，放行是对的，但它把「放宽」和「换库」当成同一类处理。更要紧的是 `mode="all"` 存的是「所有启用的库」这条规则，管理员新建或停用一个库都会让范围被动变化，这个判断会被目录层的异步变化牵着走。否决。

**换范围就开新会话。** 隔离由会话边界天然完成，最硬。代价是把界面上的一个选择升格成会话生命周期事件，连带影响会话列表、归属表、续跑与清理。为一个提示词就能扛的风险付这个代价不划算。否决。

## Consequences

**「模型不重新检索、直接复述旧结论」没有硬拦**，只剩提示词。这种失败在界面上是静默的：前端只标记带 `[[E...]]` 却解析不出的引用，模型干脆不写引用时没有任何提示。

**每次调用的输入 token 明显变长。** 过去历史里只有几十字的提问，现在是整段 Tool 原文与回答，费用与延迟都会上去（走中转站不保证 prompt 缓存能抵一部分）。压缩改用窗口占比正是为了给这件事设上限。

**被压缩那段的原文细节不进摘要。** 先清后压意味着摘要模型读到的是「问题 + 回答 + 已清空的 Tool 占位」，摘要因此是问答的浓缩而不是文档正文的浓缩；模型需要细节只能重新检索。

**窗口占比依赖近似 token 计数**，上游不报用量时退化成纯估算，80% 这个触发点会偏早或偏晚。

**换范围后旧范围的原文与旧回答确实会进入上下文**，这是本决策的直接结果，靠提示词约束用途。

**清理会改 checkpoint 的状态**，所以「用户永远看得到完整对话」不再是 checkpoint 能保证的事，必须依赖会话历史业务表（[0044](0044-session-history-in-own-table.md)）。在业务表落地之前，被清掉那一段的工具返回内容在回看里显示成占位文字——今天那个时刻整轮会直接从回看里消失，所以这不是变差，但它是本次明确调整的用户可见行为，验收时按已接受处理。
