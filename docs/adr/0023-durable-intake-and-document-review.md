# 原件持久接收与文档解析审核分开

文件与 FreshRSS 统一接入 Docling，正常结果自动索引，异常结果等待人工处理，成功结果也允许主动复核。核心是把「接收原件」与「是否采用解析结果」拆成两件事：原先解析失败发生在 Document 保存之前，失败的资料连一条可复核、可重试的持久记录都没有；拆开之后原件与处理待办先可靠落库，解析成功与否都不影响「这条资料已被受理」这个事实。失败项留待人工而不丢掉，是因为失败原因（HTML 结构怪、正文超限、编码异常）恰恰最需要人看一眼，而重试往往只需换一种解析方式；单篇坏资料也不该长期阻塞同一个 Source 的后续内容。候选与正式版本隔离，是因为人工编辑和来源更新都不能提前影响正在使用的正文：新版本先在后台把索引准备好，成功才切换，失败保留旧版本。「拒绝」与「删除」是两个操作：拒绝只停止后续检索、Agent 取用和普通读取，原件与审核结论保留；只有明确删除才清除一切。完整时序见 [文档生命周期](../flows/file-document-lifecycle.md)。

## Considered Options

**候选直接写进正式位置，采用只是改一个标志位。** 「索引准备中」的候选会提前被检索读到，用户会看到一会有一会没有的结果；先写独立索引实例、成功后才条件切换，代价是要维护多个索引实例的生命周期与回收。

**人工拒绝等同于删除。** 拒绝往往是「这篇解析得不好，先别用，我以后再看」，合并两者会让一次犹豫变成不可恢复的数据丢失。

## Consequences

待审核、失败和拒绝记录不按保留期自动清理，保留期不替人工做审核决定；定时清理只选择已完成索引的正式资料，存在待处理候选时不因旧正式版本到期而连同候选删掉。未采用的编辑草稿只保留最新一份，且不允许被来源同步覆盖。来源导入的游标前进只表示此前资料已可靠接收，不表示其解析结果已采用或索引完成。
