# 原件持久接收与文档解析审核分开

2026-09-08，老板确认文件与 FreshRSS 统一接入 Docling、正常结果自动索引、异常结果等待人工处理，且成功
结果也允许主动复核。**核心是把「接收原件」与「是否采用解析结果」拆成两件事**：原先是解析失败发生在
Document 保存之前，于是失败的资料连一条可复核、可重试的持久记录都没有。拆开之后，原件与处理待办先
可靠落库，解析成功与否都不影响「这条资料已被受理」这个事实。

后台执行由 [ADR 0019](0019-scheduled-execution-and-write-coordination.md) 的公共任务组件承担。完整的
接收、解析、审核、采用、拒绝与删除时序见 [文档生命周期](../flows/file-document-lifecycle.md)；精确
表结构、状态与错误契约以 schema、代码和测试为准。本文只记决策与理由。

**为什么失败项要留待人工而不是丢掉。** 单篇坏资料不该长期阻塞同一个 Source 的后续内容，所以接收位置
的推进以「资料已持久保存」为前提、不以「解析成功」为前提——存储失败不能当作可跳过的解析异常。相应地，
按可检测的异常拦截（解析报错、没有有效正文或 Chunk、正文或标题因超限被丢弃），其余结果自动进入索引
流程。这些检查不保证发现全部语义缺失，所以已成功处理的结果仍提供主动复核入口。

**为什么候选与正式版本必须隔离。** 人工编辑和来源更新都不能提前影响正在使用的正文，所以人工修改先
作为待确认结果，确认采用后才参与正式正文与索引更新；新版本要先在后台把索引准备好，成功后才切换，
失败则保留旧版本。没有旧正式版本的资料在索引准备成功并完成采用前，不对普通读取和检索开放。版本切换
也不能把一篇 Document 的不同版本混成一组检索结果——这正是
[ADR 0001](0001-backend-owns-result-uniqueness-and-order.md) 要按索引实例分组的原因。

**「拒绝」与「删除」是两个不同操作。** 人工明确拒绝只停止该资料的后续检索、Agent 取用和普通全文读取，
原件、正式历史与审核结论都保留供后续修正；只有明确删除（或符合条件的定时清理）才清除原件、草稿、
正式历史、审核记录与向量索引。这条区分让「我不想要它出现在结果里」和「我要它彻底消失」不再共用一个
动作。

## Considered Options

**解析失败就丢弃资料，只记录一条日志。** 实现最简。但失败原因（HTML 结构怪、正文超限、编码异常）
恰恰是最需要人工看一眼的情况，日志在页面上看不见，也无法重试——而重试往往只需要换一种解析方式。
持久化失败记录的代价是接收路径要区分「存储失败」与「解析失败」，这个代价换来的是坏资料可定位、可
重试、可审核。

**候选直接写进正式位置，采用只是改一个标志位。** 少一次切换。但这样「索引准备中」的候选会提前被检索
读到，而它可能解析失败或还没索引完；用户会看到一会有一会没有的结果。先写独立索引实例、成功后才条件
切换，代价是要维护多个索引实例的生命周期与回收，换来的是「用户永远只看到一份可用的正文」。

**人工拒绝等同于删除。** 少一个状态。但拒绝往往是「这篇解析得不好，先别用，我以后再看」，真正想彻底
清掉是另一个决定；把两者合并会让一次犹豫变成不可恢复的数据丢失。

## Consequences

**留存换来的是可核对与可重新解析，代价是生命周期协调。** 原件、正式历史、审核结论分别持久保存，
兼容重建复用正式版本的冻结清单，改变 Chunk 规则必须重新预览和采用。跨存储恢复保留原件与索引实例依据。

**待审核、失败和拒绝记录不按保留期自动清理。** 保留期不替人工做审核决定——代价是这些记录会持续占用
存储，需要人工处理或明确删除。定时清理只选择已完成索引的正式资料；存在尚待处理的候选时，不因旧的
正式版本到期而连同候选一起删掉。保留期按发布日期起算，没有发布日期时用创建时间。

**未采用的编辑草稿只保留最新一份。** 把每次修改都扩展成一份完整文档历史，成本远大于收益；而人工
草稿不允许被来源同步覆盖（来源更新时保留草稿、另存最新来源内容并提示人工决定），因为那会丢掉人工
刚做完的修正。

**这调整了来源导入的既有顺序。** 原先「全部解析通过后保存 Document 并推进 checkpoint」，现在游标前进
只表示此前资料已可靠接收，不表示其解析结果已采用或索引完成。后台待办持久化不等于允许自动抢占旧写入，
进程中断或远端写入结果不确定时仍遵守 ADR 0019 的人工恢复边界。Source 与 KnowledgeBase 的准入规则继续
沿用 [ADR 0020](0020-knowledge-base-management-slice.md)。
