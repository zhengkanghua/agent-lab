# 会话级系统提示词在建立时固定

系统提示词此前是每轮请求的参数，前端每轮发上来、后端直接装进本次运行，既不落库也不读会话。本决策把它改成会话级：建会话时从账号的个人偏好读一次、写进 `agent_threads`，此后这个会话的每一轮都用这份值、中途不可改；账号改了偏好只影响新开的会话，请求体里的 `system_prompt` 字段随之删除。要固定有两个原因：一是回放看不出当时用了什么设定——提示词不进消息历史，回头看一条历史回答时无法知道它是在哪份提示词下产生的；二是去掉一个由客户端引入的前缀不稳定来源——上游中转站对前缀稳定的请求做缓存计费，而每轮由浏览器重送提示词，前端存储或组装稍有变化前缀就变。第二条收益有明确上限：提示词末尾的日期段跨过零点必然变化，本文只承诺去掉客户端引入的不稳定来源，不承诺缓存持续命中。

## Considered Options

**提示词写进用户消息的 `additional_kwargs`，供回放读取。** 那是运行级元数据的口袋（`run_id`、`scope` 每轮都可能不同），提示词是会话级属性，两个层级不该共用同一个口袋；而且它会让系统提示词进入 checkpointer 的消息历史。

**会话已开始后在设置页把编辑器置灰。** 设置页的编辑框管的是后续新会话，灰掉它用户就没法为下一个会话准备提示词，是功能损坏。

## Consequences

`agent_threads` 里 `system_prompt` 与 `scope` 两列的写入语义相反，这是有意的：`scope` 续聊时请求带了就覆盖，`system_prompt` 建立后不变、续聊不重读偏好。后来的人容易以为其中一处写漏了、顺手「修」成一致，那会分别破坏 `scope` 的改选能力或提示词的恒定性。
