# ADR 0016: 检索页检索流采用独立的加宽列（--stream-width）

## 上下文 (Context)

语义检索页的单列宽度沿用 `--reading-width`（760px）。这个值是为 Agent 对话页的纯正文
阅读定的（一行约 68 个全角字符以内，避免来回扫视），结果卡的正文片段照搬后，检索页
在 1440px 及以上的屏幕上左右各空出约 300px，屏幕利用率刚过一半；结果卡本身是
「来源标签 + 标题 + 片段正文 + 操作行」的混合排版，不是纯正文，可以承受更长的行。

老板在 2026-09 的前端审查中提出「检索出来的页面不够宽」。经讨论选定折中方案：
加宽到 960px（约 60～65 个全角字符/行），而不是拉满 `--content-width`（1420px，
单列正文会回到一行 140+ 字符的老问题），也不是把阅读面板改成常驻双栏（改动大，
另立话题）。

## 决策 (Decision)

1. 新增设计令牌 `--stream-width: 960px`，专指检索页检索流（时间线 + 结果卡）的列宽；
   `SearchPage` 的输入坞与检索流容器改用它（外层保持 `+80px` 的呼吸空间）。
2. `--reading-width`（760px）继续专用于纯正文阅读列（Agent 对话、阅读面板内的正文），
   两个令牌各管一种排版，不再共用。
3. 结果卡正文片段的行长上限从 `max-width: 82ch` 改为 `65em`：`ch` 量的是「0」字宽，
   对全角正文偏窄一截；`65em` 即约 65 个全角字符，随字号缩放，在 960px 列宽下是
   不再收紧的自然上限，保证令牌再加宽时行长也不会失守。
4. Agent 对话页宽度不变。

## 后果 (Consequences)

* 检索页在宽屏上空白明显减少，结果卡与输入坞同宽，视觉重心居中。
* 片段正文一行约 60～65 个全角字符，处于舒适阅读区间上沿；折叠标题行、来源标签
  等混合排版元素获得更多横向空间。
* `--stream-width` 是检索页专属令牌：如果未来把阅读面板改成常驻双栏（方案 B），
  这个令牌和本 ADR 一起重审。
* 消融说明：评估过用容器查询按视口动态分档（760/960/1200），放弃——多一档就多一个
  需要截图核验的状态，而单一 960px 已覆盖老板提出的「不够宽」，先保持最简。
