# KnowledgeBase 从配置切片扩展为通用应用组件

KnowledgeBase 从「只交付配置」的初次切片扩展为完整的知识库应用边界：Source 绑定、Document 归属、检索范围与清理过滤成组接入，多个库共享同一批表与同一个 Collection、靠 `knowledge_base_id` 隔离。停用是可逆的配置变化，不删数据，但拒绝新增绑定、来源导入和检索。索引与文档构建的部分已由 [0022](0022-pluggable-document-processing.md) 与 [0023](0023-durable-intake-and-document-review.md) 取代，本文只剩下面三条。

**做成进程内组件而不是独立服务。** 配置是所有数据隔离的共同前置，但它本身足够简单，当前只有一个运行时在用；引入网络调用、部署单元和跨服务事务协调，成本远大于收益。

**检索必须明确范围，缺省不跨库。** 新页面显式选择所有启用库或非空 ID 集合，旧 HTTP 缺省仍明确传 `news`，空选择或显式 null 不退化为无过滤查询。让搜索接口在缺省时自动跨所有库对旧调用方更「方便」，但会让一次部署静默改变既有调用的语义，旧页面突然开始返回别的库的内容。

**重建完整构建并验收新代次之后才把 current Alias 指过去。** 构建失败保留原指向，发布结果不确定时保留占用供人工核实，旧 Collection 不自动删除。

## Considered Options

**保留两套导入服务并存一段时间，回退更容易。** 两套路径共享同一批 Document 与 Qdrant 写入，并存期间谁改了什么说不清；删除转接层后行为回归照样通过，证明并存没有换来任何东西。
