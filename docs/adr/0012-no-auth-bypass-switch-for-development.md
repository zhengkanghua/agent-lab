# 开发环境不提供跳过认证的开关

本地开发和测试时仍然走真实登录：真的 `POST /auth/login`、真的 HttpOnly Cookie、后端每个请求真的校验。
仓库里不存在任何「打开某个配置就不用登录」的代码路径，前后端都没有。为了不让这件事变烦，改用两个
不碰认证的办法：登录会话时长本来就可配（`AUTH_SESSION_LIFETIME_SECONDS`，默认 8 小时，本地可调到几天），
以及开发模式下把登录表单预填好，凭据放在已被 `.gitignore` 忽略的 `frontend/.env.local` 里。

否掉开关的理由不是它难做，而是**它失效时没有任何症状**。一个 `AUTH_DEV_BYPASS=true` 如果哪天以默认打开的
状态出现在线上，表现是全站零门槛敞开：没有报错、没有异常日志、健康检查通过、页面一切正常，
只是所有人都能读所有数据。这类故障要靠人主动去怀疑才会被发现，而它恰好长成一个「配置项」的样子，
在 `.env.example`、部署脚本、容器环境变量之间被复制粘贴时没有任何一环会拦它。相比之下，
本项目要省的成本是「八小时登录一次」，两边不成比例。

## Considered Options

**后端开关（`AUTH_DEV_BYPASS=true`），把每个请求都当成某个固定超级用户。** 功能上最彻底，所有接口
真能用，检索、Agent 对话、账号管理全通。可以加三道锁降低风险：只读 `.env` 不读命令行、启动时若
`AUTH_COOKIE_SECURE=true`（即长得像生产）就拒绝启动、每个请求打一行醒目告警日志。但三道锁齐了它仍然
比其他方案危险一个量级，因为那三道锁本身也是配置，也会被复制粘贴，而且第二道锁在「生产忘了开
`AUTH_COOKIE_SECURE`」的情况下反而失效——那正是最该拦住的场景。

**前端假装已登录（`import.meta.env.DEV` 门内，伪造 `/auth/me` 的返回）。** 安全上其实很干净：Vite
在生产构建时把 `import.meta.env.DEV` 静态替换成 `false`，那段代码连字节都不会进产物，物理上无法在线上
生效。但它只骗了界面——真去点检索或 Agent 对话，请求照样被后端 401 挡回来。所以它只能用来看样式和
交互，跑不通任何业务流程。看样式这件事已经有 Playwright route mock 在做（能同时造出普通账号、
超级用户、环境管理员三种视图来对比），不需要再引入一个只解决同一半问题的机制。

**在测试里绕过，不在运行时绕过。** 后端 HTTP 测试已经用 `tests/auth_helpers.py` 覆盖认证依赖，
前端组件测试直接给定会话状态。这条其实已经在用，而且是对的——它被列在这里是为了说明：
「不用登录」的需求在自动化测试里早就被满足了，剩下的只是人工点页面时的便利，那部分不值得动认证。

## Consequences

**本地要保留一份凭据文件。** `frontend/.env.local` 里放开发用邮箱和密码，`.env.example` 补上这两个键的
说明但值留空。`frontend/.gitignore` 已经忽略 `.env.local`，凭据不进仓库。代价是新人 clone 下来要自己
填一次，比一个开关麻烦，但那一次成本换掉的是一类不会报错的线上事故。

**预填只填不提交。** 预填后登录按钮还是要点一下，不做自动提交。自动提交等于把「跳过登录」用另一种
方式实现出来，而且会让登录页在开发时无法被正常测试——想验证错误提示就得先把预填关掉。

**这条约束不随环境放松。** 以后加 staging 或 preview 环境时，同样走真实登录，不为「反正不是生产」
开例外。理由和上面一样：例外一旦存在，判断「这个环境算不算生产」就成了每次部署都要重做的人工判断。

**如果哪天真的需要免登录（比如做端到端冒烟测试），走的是发一个短时效的真实 token，不是绕过校验。**
那是「用真凭据自动登录」，与本 ADR 不冲突；本 ADR 禁止的是「不校验也放行」这条代码路径存在。
