# 开发环境不提供跳过认证的开关

本地开发和测试仍走真实登录，仓库里不存在任何「打开某个配置就不用登录」的代码路径；省麻烦的办法是登录会话时长可配（本地调到几天）和开发模式下预填登录表单，凭据放在不进仓库的 `.env.local`。否掉开关的理由不是它难做，而是它失效时没有任何症状：一个 `AUTH_DEV_BYPASS=true` 哪天以默认打开的状态出现在线上，表现是全站零门槛敞开——没有报错、健康检查通过、页面一切正常。这类故障要靠人主动去怀疑才会被发现，而它恰好长成一个「配置项」的样子，在 `.env.example`、部署脚本、容器环境变量之间被复制粘贴时没有任何一环会拦它。相比之下要省的成本是「八小时登录一次」，两边不成比例。

## Considered Options

**后端开关，配三道锁降低风险（只读 `.env`、长得像生产就拒绝启动、每请求告警）。** 三道锁本身也是配置、也会被复制粘贴；「长得像生产就拒绝启动」那道锁在生产忘了开 `AUTH_COOKIE_SECURE` 时反而失效，那正是最该拦住的场景。

**前端在 `import.meta.env.DEV` 门内伪造登录态。** 生产构建会把那段代码整个剔掉，安全上干净，但它只骗了界面，请求照样被后端 401 挡回，跑不通任何业务流程。

## Consequences

预填只填不提交，自动提交等于用另一种方式实现了跳过登录。这条约束不随环境放松，staging 或 preview 同样走真实登录：例外一旦存在，「这个环境算不算生产」就成了每次部署都要重做的人工判断。真需要免登录（比如端到端冒烟测试）时走的是发一个短时效的真实凭据，本文禁止的是「不校验也放行」这条代码路径存在。
