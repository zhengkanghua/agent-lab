# Agent 对话对所有登录账号开放

Agent 对话此前只对超级用户开放，本决策把它放开给所有已登录账号，超级用户身份保留、管理后台仍只对它开放。能放开有两个原因：一是它锁的是一个访问控制问题，而那个问题已经由 [0009](0009-agent-thread-ownership-in-own-table.md) 单独解决——会话归属按账号判断而不按角色，不属于当前账号一律 404，放开权限不会重新打开跨账号读对话的洞；二是能力本身只读（[0003](0003-agent-v1-is-read-only.md)），它读的知识库内容检索页本来就对普通账号开放，放开不新增任何数据暴露面。继续只给超级用户，等于把访问控制寄存在一个与它无关的角色设置上，变更点和事故点离得很远。

## Considered Options

**放开的同时加模型额度限制。** 老板判定不存在这个需求：账号都是内部人员，不对外开放。代价如实记录在下面，不靠限制去抵消。

## Consequences

模型额度对所有登录账号共享，账号变多账单就线性涨，这是直接代价不是意外。自定义系统提示词一并放开，它戴着护栏：中间件在选定提示词之后追加应用规定的资料边界，所以它能改的只是回答风格，扩大不了知识库范围。放开之后跨账号隔离是唯一的屏障，「归属条件只写在 `AgentThreadService` 一处」这条约束变得更重要。
