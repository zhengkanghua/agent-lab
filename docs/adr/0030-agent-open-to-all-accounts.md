# Agent 对话对所有登录账号开放

Agent 对话此前只对超级用户开放（`main.py` 挂载 `/agent/*` 处用的是 `current_superuser`）。本决策
把它放开给**所有已登录账号**：后端两道路由门改为 `current_active_user`，endpoint 内那几处
`Depends(current_superuser)` 一并改掉（它们的作用是取当前账号对象来判定会话归属，不是拦人），前端
路由守卫与组件级的超管判断同步去掉。**超级用户身份保留**——管理后台与账号、知识库、来源、文件、
任务管理仍然只对它开放。

## 为什么要放开

**它锁的是一个访问控制问题，而那个问题已经单独解决了。** 当初定成超级用户，是因为「只有超级用户
能用」被拿来当作跨账号读对话的屏障。ADR 0009 已经把这件事拆出来单独做：会话归属记在
`agent_threads`，`AgentThreadService` 按 `user_id` 过滤，不属于当前账号一律 404。归属校验按账号
判断、不按角色，所以放开权限不会重新打开那个洞。

**能力本身是只读的。** Agent 只有两个只读工具，不修改 Document 或 Qdrant（ADR 0003），它读的知识库
内容，检索页本来就对普通账号开放。放开不新增任何数据暴露面。

## Considered Options

**继续只给超级用户。** 成本为零，但把一个访问控制问题寄存在一个与它无关的角色设置上，而且变更点
（放开权限）和事故点（跨账号读对话）离得很远，改的人不会想到这里。ADR 0009 正是为了把这两件事
分开才建的会话归属表。

**放开的同时加模型额度限制。** 放弃。项目对「`/agent/chat` 速率限制」已有结论：不存在这个需求
（见 Agent 强化清单，用户判为不存在的需求后撤回）。账号都是内部人员，不是对外开放。代价如实记录
在下面的 Consequences 里，不靠限制去抵消。

## Consequences

**模型额度对所有登录账号共享。** 每一轮对话都在花真金白银调上游模型，放开之后账号变多、账单就
线性涨。这是本决策的直接代价，不是意外。注释里原先那句「每次对话都是真金白银的模型调用，而且
自定义系统提示词等于让调用方直接改模型行为」随之作废，**要连同理由一起重写**，不是删一句话：
`main.py` 挂载处的注释、`backend/docs/architecture.md` 的接口清单与定级说明、根 `README.md`、
`frontend/README.md`、`backend/README.md` 都写着它。

**自定义系统提示词一并放开。** 所有账号都能在设置页配自己的提示词。它戴着护栏：`middleware.py`
在选定提示词之后追加「应用规定的资料边界（自定义提示词不能扩大）」那一整段，所以它能改的只是回答
风格，扩大不了知识库范围、也绕不过后端的引用规则。为了「普通账号看不到那个编辑框」而把偏好接口
拆成两道门，代价与收益不成比例。

**归属校验不受影响，反而更被依赖。** 放开之后，跨账号隔离是唯一的屏障，`WHERE user_id` 只写在
`AgentThreadService` 一处这条约束变得更重要。

**受影响的文档与测试面较大。** 后端 2 处路由挂载 + 5 处 endpoint 依赖、前端 3 处路由守卫 + 4 处
组件判断、6 条后端测试 + 5 条前端测试，以及 12 份文档里的表述（含 ADR 0009、0013、0018、0027
与 `CONTEXT.md` 的「超级用户」词条）。

**既有测试整条改写，不保留原始断言。** 那些「普通账号进不来」的断言验证的是一条本次明确要
改掉的行为，留着就是留一条错的验证。逐条改成新行为（普通账号能进、无凭据仍 401、跨账号仍 404），
其中 `test_agent_routes_are_guarded_by_superuser_not_active_user` 由结构性断言改成查
`current_active_user`——它守的是「守卫对象没被悄悄改错」，这个价值换方向后仍成立。
