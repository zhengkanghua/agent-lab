# 检索页重构为多轮检索流，去掉按片段

检索页 `/` 由「单次覆盖式搜索」重构为一条仿 Agent 会话体感、向下累积的检索流：顶部常驻一条输入框，
最新一次检索的记录顶在输入框正下方完整展开，旧记录折叠成「检索词 + 命中数」的标题行往下沉、可点开
回看；每次搜索追加一条，刷新/离开即清空。同时**去掉了「按片段」模式**，前端只走按文档分组的
`POST /document-search`。检索页仍是普通账号可用的纯只读原文检索，不做真会话、不引入账号级历史存储。
页面形态与交互细节见 [前端 README](../../frontend/README.md)，链路终态见
[单次检索流程](../flows/one-search.md)。

**为什么是「仿会话」而不是真会话。** 老板希望检索页「和 Agent 会话一样合并」，但明确不是并入
`/agent` 页面、也不做 Agent 那种服务端会话——只是体感像：输入与检索内容在一条连续向下的流里，多次
检索能回看。逐轮确认的形态是「最新 = 最靠近输入框」。改动前的代码是一个单次请求状态机外加两种模式
切换，第二次搜索会覆盖第一次、旧结果没法回看。

## Considered Options

**仅视觉合并，仍单次覆盖。** 改动最轻，但没有解决「每次搜索顶掉上一次、不能回看」这个老板最在意的
与 Agent 的差距，体验仍割裂。

**真正账号级会话化（跨刷新、跨设备持久检索历史、带侧栏会话列表）。** 普通账号目前没有任何检索历史
后端，做它等于新开一个后端能力域加写库，成本和范围远大于本轮目标，故不做。

**保留按片段模式。** 提供一个和文档级几乎同构的 Chunk 级展示需要持续维护两套结果组件与两套状态。
老板选择「直接去掉按片段」，前端按片段组件与状态代码全部删除；后端 `/vector-search` 的 Chunk 级契约
与单测保留——那不是把该接口从后端删除。

## Consequences

**改动集中在 `frontend/`，纯前端重构。** 搜索仍走既有 `/document-search`，接口与 OpenAPI 契约不变，
不新增后端能力。

**可见行为变化是有意的。** 原来搜第二次会替换第一次的结果；现在多次搜索累积成可回看的检索流。这份
历史仅存在于当前页面会话，刷新即清空——和 Agent 那种服务端持久化会话是两回事，避免用户误以为检索
历史会被账号保存。检索记录的状态就是组件内的 `shallowRef`，整条链路没有 localStorage、sessionStorage
或后端历史端点。

**权限边界。** 检索页仍是登录即可用的只读页，且仍不写业务表与 Qdrant。重构当时「Agent 页仍仅超级
用户」的那半句已由 [ADR 0030](0030-agent-open-to-all-accounts.md) 取代：Agent 对话现已对所有登录账号
开放，只读这一条不变。

**术语落档。** 新增「检索记录 / 检索流」入 `CONTEXT.md`，并显式与 Agent 侧的「运行(run)/会话(thread)/
轮(turn)」区分，避免两边混用。
