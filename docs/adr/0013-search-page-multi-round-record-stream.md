# 检索页重构为多轮检索流，去掉按片段

检索页 `/` 由「单次覆盖式搜索」重构为一条仿 Agent 会话体感、向下累积的检索流：顶部常驻一条
输入框，最新一次检索的记录顶在输入框正下方完整展开，旧记录折叠成「检索词 + 命中数」的标题行
往下沉，可点开回看；每次搜索追加一条，刷新/离开即清空。同时**去掉了「按片段」模式**，前端只走
按新闻分组的 `POST /document-search`。检索页仍是普通账号可用的纯只读原文检索，不做真会话、
不引入账号级历史存储。

## Context

老板希望检索页「和 Agent 会话一样合并」，但明确不是并入 `/agent` 页面、也不做 Agent 那种服务端
会话——只是体感像：输入与检索内容在一条连续向下的流里，多次检索能回看。逐轮确认的形态是
「最新 = 最靠近输入框」：输入在上则最新贴顶、旧记录沉下（Q1–Q15）。代码现状是一个单次请求状态机
`useSearchRequest` + 两种模式（按新闻/按片段）切换，第二次搜索会覆盖第一次，旧结果没法回看。

## Considered Options

**（甲）仅视觉合并，仍单次覆盖。** 改动最轻，但没有解决「每次搜索顶掉上一次、不能回看」这个
老板最在意的与 Agent 的差距，体验仍割裂。

**（乙）多轮累积的检索流（选定）。** 每次搜索固化成一条「检索记录」，多轮向下累积、旧记录折叠可回看；
记录只存在页面内存，刷新即清。纯前端改动，不需要后端会话存储。搜索量大，但结果轮次多时折叠标题行，
页面不会失控。只在「新检索会取消上一条在途请求」时删掉中途放弃的 loading 占位轮，保证每轮状态干净。

**（丙）真正账号级会话化。** 跨刷新/跨设备持久检索历史、带侧栏会话列表。普通账号目前没有任何检索
历史后端，做它等于新开一个后端能力域 + 写库，成本和范围远大于本轮目标，故不做。

**关于按片段：** 提供一个和按新闻几乎同构的 Chunk 级展示需要持续维护两套结果组件与两套状态。老板
选择「直接去掉按片段」，前端随之删除 `useChunkSearch` / `SearchResults` / `ChunkResultCard` /
`useSearchRequest` / `api/vector-search.ts` 及其 spec；后端 `/vector-search` 契约与单测保留。

## Consequences

**改动集中在 `frontend/`，纯前端重构。** 新增 `SearchRecord` 模型与 `useSearchStream`（多轮累积、单活动
请求、陈旧响应守卫、清空），`SearchComposer` 改为顶部常驻输入条（去模式切换、全局数量参数 + 清空入口），
新增 `SearchRecordTurn`（单条记录的折叠/展开与 loading/空/错/结果四态），`SearchPage` 改为「最新贴顶、
旧记录折叠」渲染；`DocumentReader` 与 `SearchResultCard` 复用。搜索仍走既有 `/document-search`，接口与
OpenAPI 契约不变，不新增后端能力。按片段相关前端文件与 spec 删除，`shared-styles.node.spec.ts` 与
`result-card.css` 注释同步。

**可见行为变化是有意的。** 原来搜第二次会替换第一次的结果；现在多次搜索累积成可回看的检索流。
这份历史仅存在于当前页面会话，刷新即清空——和 Agent 那种服务端持久化会话是两回事，避免用户误以为
检索历史会被账号保存。

**普通账号与超管的边界不变。** 检索页仍是登录即可用的只读页；Agent 页（`/agent`）仍仅超级用户，
且仍不写业务表与 Qdrant。前端不再从检索页调用 `/vector-search`，但那不是把该接口从后端删除。

**术语落档。** 新增「检索记录 / 检索流」入 `CONTEXT.md`，并显式与 Agent 侧的「运行(run)/会话(thread)/
轮(turn)」区分，避免两边混用。
