# 检索页重构为多轮检索流，去掉按片段

检索页由「单次覆盖式搜索」重构为一条向下累积的检索流：记录按提交先后从上往下排，最新的一条在最下面、贴着底部输入坞展开，旧记录折叠成标题行留在上方、可点开回看，刷新或离开即清空。同时去掉「按片段」模式，前端只走按文档分组的 `POST /document-search`。老板希望检索页「和 Agent 会话一样合并」，但明确不是并入 `/agent`、也不做服务端会话——只是体感像：多次检索在一条连续的流里、能回看，而改动前第二次搜索会覆盖第一次、旧结果没法回看。

输入坞在页面底部而不是顶部是**有意的**（2026-10 调整，原先为顶部常驻 + 最新记录贴顶）：这是「体感像 Agent 会话」的一部分，检索页因此与 `/agent` 同形态——输入坞贴底、内容往上长、记录区只在用户仍贴底时跟随滚动。搜索框放顶部是更常见的做法，改回之前请先看这条：顶部排布下要维持「最新结果紧挨输入框」，记录顺序必须跟着翻转，只挪位置会让最新结果落在远离输入框的页面顶端。

## Considered Options

**真正账号级会话化（跨刷新、跨设备的检索历史）。** 普通账号没有任何检索历史后端，做它等于新开一个能力域加写库，远超本轮目标。

**保留按片段模式。** 一个和文档级几乎同构的 Chunk 级展示要持续维护两套结果组件与两套状态，老板选择直接去掉；后端 `/vector-search` 的 Chunk 级契约与单测保留，那不是把接口删除。

## Consequences

检索记录只存在于当前页面内存，整条链路没有 localStorage、sessionStorage 或后端历史端点，用户不会误以为检索历史会被账号保存。检索页仍是登录即可用的只读页，不写业务表与 Qdrant。
