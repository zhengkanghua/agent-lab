# 模型目录由平台配置，用户在会话里选择

平台此前只有一个模型：上游地址、凭据和模型名全在环境变量里，进程启动时构造一个客户端，失败时降到同样写死的备用模型。这次改成**目录制**：平台在后台配好若干**上游渠道**（显示名、接入类型、地址、凭据）和挂在渠道下的**可用模型**（上游模型名、展示名、上下文窗口），用户在会话里挑一个用，没挑就用标着默认的那一个。

客户端那一层不用新造抽象：一行渠道就是一份 `LlmSettings`，直接交给现成的 `build_chat_model`。凭据在后台表单里明文填一次，后端加密落库，**读取接口永不返回它**，只回「已配置 / 未配置」，编辑时留空表示不改。主密钥从环境变量读，与今天 `LLM_API_KEY` 同一个信任边界——加密对着的是「数据库被单独读走」这个场景（备份、只读副本、只读账号），不是「服务器被拿下」。

**选择的语义与会话知识库选择同类**：会话上存一份默认，选择器一改就保存、提问请求带了也写回会话行（即「改了就是记住」，没有「只对这一次」的单次覆盖），每轮实际用的那个另外冻结进本次运行。冻结时**连展示名一起快照**，照 `KnowledgeBaseSummary`「查询时的展示快照，改名后不改写历史记录」的做法——否则条目一改名或一停用，回放里那句「本次模型：xxx」就跟着变，那是最难查的一种不一致。

**客户端的缓存把「未命中」与「变旧」分开处理**：缓存以模型 id 为键，未命中就直接查库，所以刚加的可选模型立刻可用、没有生效延迟；命中后信任 60 秒，超时只重新校验那一行的内容，**内容没变就继续复用同一个客户端**——无条件重建会让一个被频繁使用的模型每分钟丢一次连接池与 TLS 连接。改一条已有配置最多 60 秒后全副本生效，不需要任何跨进程通知。

**备用模型整个删掉。** 用户现在能自己换模型，上游不可用时让他换就是了，平台不再有兜底渠道。连带清掉 `fallback_model` 配置与 `LLM_FALLBACK_MODEL` 环境变量——留着会有人以为它还在起作用。重试保留；重试中间件的 `on_failure="error"` 从此更重要：外面没有兜底再拦一道，写成默认的 `"continue"` 会让失败伪装成成功。

**配错的模型只在运行时如实告知，不做前置拦截。** 保存时不试调（[0039](0039-swarm-start-first-deploys.md) 把启动时对模型的自检整个移除过，理由是「模型不是『能服务』的前提」，保存时试调是同一类东西），也不校验模型支不支持工具调用。只补一个**面向用户的错误码**：「你选的模型已不可用，请换一个模型再提问」——它走 HTTP 状态码而不是流里的事件，因为选择在开始运行之前解析，和范围失效是同一条路径。另外把 `llm_model_not_found` 与 `llm_authentication_failed` 的文案补上「……请联系管理员，或换一个模型试试」，它们今天落到「服务端的模型配置需要维护」，用户看完不知道该干什么。

**停用一个条目时，每一处引用都要有明确归宿。** 它是默认模型时**拒绝停用**，要求先把默认换到别处；上游渠道停用等于它下面的模型全部不可用，不去逐个改模型的启用位，两份状态必然漂移；**不提供删除**，只提供停用，与 `KnowledgeBase` 的「停用保留数据」一致。选过它的会话**不改动数据、只如实提示**：选择器读到那个 id 已不可用，显示「原来是 xxx，该模型已不可用，请重新选择」，让用户自己换。

## Considered Options

**一级目录**（每条模型自带地址与凭据）。同一个 key 下挂多个模型时凭据要存好几份，换 key 要改多处。否决。

**凭据明文入库。** 省事，代价是数据库里永久躺着一份可用凭据，任何一次读取都能拿到。否决。

**保留失败降级。** 这是今天的形状，能扛某个上游整体不可用。否决的理由是用户已经能自己换模型，而它的代价是「用户选了 A 渠道、失败时内容被发到 B 渠道」这件不容易向用户解释的事；那条代价改记在下面。

**停用时静默清空会话的选择。** 看起来更干净，实际制造了更难查的误解：用户以为还在用原来的模型，平台已经悄悄换成了默认，而且没有任何地方留下痕迹。否决。

## Consequences

**平台不再有兜底渠道**：某个上游整体不可用时，用户看到的是失败，得自己换模型。

**配错的模型只在运行时暴露**，靠错误码提示；管理员把模型名或地址写错，要有人真的用到它才会发现。

**改一条已有配置最多 60 秒后全副本生效**，这是换「不需要任何跨进程通知」的。新建条目没有这个延迟。

**数据库里存着加密的凭据**，主密钥在环境变量里，所以它挡不住「服务器被拿下」，只挡「库被单独读走」。

**每个被用过的模型各占一个缓存的客户端连接池**，随被选中的模型数增长，受缓存淘汰约束。

**停用一个模型的后果是一批会话在被打开时提示重选**，不是自动修复：选择器要多一个失效态与对应文案。
