# 部署时把在途运行排空并交给新进程续跑

部署与任何优雅重启不再靠在旧进程里把整次运行等完：旧进程收到退出信号后把在途运行**排空**——等它做完当前 superstep、状态落盘——在会话行上记下「被排空、等接手」再退出；集群里任一进程扫到这个标记后，用同一个会话、以「无新输入」的方式接着把这次运行跑完。用户在界面上不感知，连接会断一次，界面短暂显示「正在生成」，随后拿到完整答案。守住这个能力的前提是两次部署之间**图状态结构**没变（见 `CONTEXT.md` 与下面「Considered Options」）。

## Considered Options

**继续靠「旧进程等连接」把它跑完。** 这是改动前的实际形态：ASGI 服务器要等已有连接与任务结束才走收尾，而那条 SSE 连接要开到运行结束，所以部署的等待时间等于整次运行的长度（宽限期 360 秒，另一份规格原本打算放宽到 600 秒）。否掉是因为它把「一次部署等多久」挂在「一次运行跑多久」上，而按有界执行常量的最坏组合，一次运行能拖到小时级；而且这个机制依赖浏览器那条连接还开着——用户关掉页面再赶上一次部署，那次已经付过费的运行就被砍掉，恰好是 0035 要消灭的那一类。

**把运行搬进 Celery（仓库已有这套设施）。** 见 0035 的取舍：要把图、模型客户端与 checkpointer 的装配搬进 Worker，事件还要跨进程传；本次要的东西（换个进程接着跑）不用搬家就能拿到。

**改用 LangGraph 平台（自托管 Agent Server 或托管云）。** 它把运行所有权、排空、队列与可续流都做成了产品，代价是自托管要拿到授权、自定义认证只对托管云或企业自托管开放，而且现有那套自研的 SSE 契约、会话归属、回放与停止接口都要被平台 API 替换。规模上也不需要它：并发运行数与注册人数不是一回事，到上千人时先撞上的是模型配额与数据库连接。记成「将来按判据再评估」，不是本次方案。

**排空后由任一进程接手（本决策）。** 只多两样东西：会话行上一个「被排空、等接手」的标记，和一个扫描它的接手者。

## Consequences

**能给的和不能给的边界必须成对记住。** 排空是优雅退出路径上的动作，覆盖部署、手动重启与以后的多副本滚动更新；**强杀、OOM、断电不属于这一类**——那时没有任何代码被执行，运行按 0036 收尾（补写已输出内容、标未完成），不续跑。改了图状态结构的发布同样不保证续跑；而形状改动有两种表现，抛异常的那种接手时能发现，静默改变合并规则的那种发现不了，只能靠发布纪律（改形状的发布挑没人在跑的时候发）。

**放弃是一条必须存在的收尾路径。** 它有两个触发点：排空等待超时时由旧进程自己收尾（**不写标记**），以及**认领之后**失败时（重建不出运行上下文、接手后运行中途抛错）由接手者收尾（标记在抢到时已被消费掉）。**图装配不起来不属于这一类**——那是认领之前的一步检查：拿不到可用的图就不认领，把标记留给能跑的进程，否则一个坏副本会替健康副本把可接手的运行收成未完成。两种都把那次运行收成未完成、解锁会话；否则那个会话既接不上旧运行、又不接受新提问。**标记本身不按时间放弃**：只要有一个进程在扫，它就会被接走；一个进程都没有的时候也没有请求被服务，定时放弃没有意义。**带「等接手」标记的会话不能被一次新提问直接顶掉**（占位那条条件写入的失活分支要排除它）：旧的 checkpoint 停在半途、还有待跑的节点，新提问会顺着那份状态继续跑旧节点，把两轮的语义搅在一起。

**等待的上限不再挂在运行时长上。** 排空的等待单位是一个 superstep（一次模型调用或一批工具调用），只有病态重试才触及上限；所以容器停止宽限期可以从 600 秒降到百秒级，CI 的部署等待跟着变短。排空的触发点放在 ASGI 生命周期收尾里，不自己装信号处理器——uvicorn 收到退出信号后先停止接受连接、等已有的连接与任务结束（用它的关停超时兜底），最后才走生命周期收尾，而运行已经与连接解耦，那条连接被掐断不影响运行。

**「续跑」不是用户功能。** 界面不提供入口、不提示、不标注，用户看到的就是回答最终出现。续不上的那些（强杀、放弃）在界面上与今天一致：看到未写完的内容，会话已解锁，可以立刻重新提问。
