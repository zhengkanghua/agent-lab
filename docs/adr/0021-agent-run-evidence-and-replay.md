# Agent 证据隔离到每次运行，终态与回看共用 checkpoint

**本页只有部分条款失效，所以状态是 accepted 而不是整份被取代。** 被取代的是三处：①「主模型只接收保留的历史问题和当前运行的消息」这条裁剪——[0045](0045-model-sees-whole-session-history.md) 撤销了它，主模型接收 checkpoint 里的整份上下文记录；②「历史压缩沿用现有机制、在新提问开始时执行并向前保留完整近期问答」这条口径——0045 改用模型窗口占比（触发 80%、压缩后保留 30%）；③「摘要可展示为背景，但不送给主模型充当证据」这句——0045 起摘要随历史一起送给模型，它从此是模型对被压缩那一段的唯一记忆。**继续生效的部分照旧**：每次运行冻结实际范围、会话知识库选择独立保存在归属表、引用标识由应用为实际 Tool 结果分配并随同一条消息保存归属与 `content_hash`、流式收尾与历史回放共用同一套证据核验、终态与引用一律从 checkpoint 取得（0045 正文已照此复述）。

同一会话允许切换 KnowledgeBase 范围，若继续把旧答案、Tool 内容或事实摘要送给主模型，切到 B 后仍可能用只属于 A 的事实作答。所以每次运行冻结实际范围，主模型只接收保留的历史问题和当前运行的消息，知识库事实必须重新取得；会话知识库选择独立保存在归属表，运行中的改选留给下一次。

引用标识由应用为实际 Tool 结果分配，随同一条消息保存归属与 `content_hash`（正文片段不再随引用另存一份）；流式收尾与历史回放共用同一套证据核验，只承认本次运行、允许范围内的成功结果——程序确认的是出处身份，不把它解释为模型结论已获事实认证。临时 token 可能来自上游重试，不能直接作为持久答案，最终文字、完成状态和引用一律从 checkpoint 取得；预算耗尽、上游截断和未持久化的中断不伪装为完整回答。

历史压缩沿用现有机制，在新提问开始时执行并向前保留完整近期问答；早期问答和引用不再逐条送给主模型，摘要可展示为背景，但不送给主模型充当证据。早期问答对用户仍可逐条回看，见 [0043](0043-session-history-outlives-summary.md)。

## Consequences

后续提问可能需要重新检索，依赖很早的问答时可能要用户补充上下文。打开引用读的是 PostgreSQL 当前全文并同时展示当时片段：`content_hash` 不能提供历史版本，也不保证索引片段能定位到原始语法中的字符位置，无法可靠定位时不高亮。压缩不承诺物理销毁旧 checkpoint。
