# 设置中心收敛偏好配置：自定义系统提示词与检索数量参数迁入 /settings

前端此前有两处「其实是配置」的东西被埋在操作路径里：**自定义系统提示词**塞在 Agent 输入区的一个折叠
面板里（它是「改变模型行为」的配置，不是一条消息；用户不点开齿轮就不会知道它存在，而且改完只影响之后
几轮、刷新即丢），**检索数量参数**藏在检索输入条的「更多设置」popover 里（它们本来就是全局一份、影响
之后所有检索的偏好，却既不可发现也不能持久）。商业产品的同类能力（自定义指令、检索偏好）都在设置页
里，所以把它们统一收敛进一个**设置中心**（`/settings/:section?`，分区由路径参数决定，可刷新可收藏），
与账号自助合并为一条可发现、可持久、可恢复默认的配置路径。分区划分与页面形态见
[前端 README](../../frontend/README.md)。

输入区只留状态入口、不留编辑器：Agent 输入条在提示词覆盖生效时亮一枚链回 `/settings/agent` 的徽章，
检索输入条保留一个直达 `/settings/search` 的图标入口。数量参数边界与提示词上界是请求契约的一部分，
放在 `api/document-search.ts` 与 `api/agent-chat.ts`——设置中心是它们的第二个消费方，事实源只有一份。

**本文有三处决策已被后续 ADR 取代**：偏好不再只存 localStorage，[ADR 0027](0027-user-level-preferences-in-database.md)
把三个偏好迁入 `user_preferences` 表（取代的触发条件是提示词的消费方从客户端转移到服务端，原文「消费方
本来就由前端组装」的前提随之失效）；提示词不再是每轮提交的参数，[ADR 0029](0029-session-scoped-system-prompt.md)
把它改成会话级快照，`getSystemPrompt` 注入点删除；Agent 偏好分区不再仅超级用户可见，
[ADR 0030](0030-agent-open-to-all-accounts.md) 对所有登录账号开放。本文其余部分（设置中心的形态与
分区划分、输入区只留状态入口、契约常量上收 `api/` 层）继续有效。

## Considered Options

**留在输入区原位，只做持久化。** 改动最小。但「不可发现」这个核心问题原样保留——埋着的配置加了
持久化，只是把隐性状态变成了隐性的持久状态。

**两个偏好各自独立成页**（检索偏好放检索页、提示词放 Agent 页，各贴各的场景）。但「配置」这个心智
模型会被拆散：用户在 A 处改了全局默认值，到 B 处找不到它。单一设置中心让「哪里改配置」只有一个答案。

**偏好存后端（账号级设置表）。** 当时否掉的理由是要新增后端能力域、迁移和接口，而这两个偏好的消费方
（每次请求）本来就由前端组装。**这条后来被 [ADR 0027](0027-user-level-preferences-in-database.md) 采纳**
——当时预判的触发条件（消费方从客户端转移到后端）真实发生了，原文保留在此以记录当时的权衡。

## Consequences

**可见行为变化是有意的。** 输入区的提示词面板与检索参数 popover 移除；偏好跨刷新保留（后来改为跨设备
保留，随 ADR 0027）。自助页与账号管理页的分离原则不变（见
[ADR 0011](0011-self-service-page-separate-from-user-admin.md)）。

**安全边界不变。** 密码与 Token 只存在于 HttpOnly Cookie。前端的条件渲染始终是体验、不是鉴权——真正
的门在后端。

**消融记录。** 评估过给设置保存配全局 Toast 通知：检索偏好是改动即生效（无「保存」动作），提示词保存
用 2.5 秒的内联确认足够，全局通知体系（ToastContainer/useToast）在全站零调用方，随本决策删除而不是
启用。BasePopover 因检索参数 popover 移除而失去唯一消费方，一并删除。
