# 设置中心收敛偏好配置：自定义系统提示词与检索数量参数迁入 /settings

前端此前有两处「其实是配置」的东西被埋在操作路径里：

- **自定义系统提示词**塞在 Agent 输入区的一个折叠面板里。它是「改变模型行为」的配置，
  不是一条消息；用户不点开齿轮就不会知道它存在，而且改完只影响之后几轮、刷新即丢。
- **检索数量参数**（document_limit / matches_per_document）藏在检索输入条的「更多设置」
  popover 里。它们本来就是全局一份、影响之后所有检索的偏好，却既不可发现也不能持久。

商业产品的同类能力（自定义指令、检索偏好）都在设置页里。本决策把它们统一收敛进一个
**设置中心**，与账号自助合并为一条可发现、可持久、可恢复默认的配置路径。

## 决策 (Decision)

1. **新增 `/settings/:section?` 设置中心**，分区由路径参数决定（可刷新、可收藏）：
   - `account` 账号安全：登录信息 + 改自己密码（原 `/account` 整体并入，旧地址重定向保留）；
   - `search` 检索偏好：两个数量参数，改动即生效；
   - `agent` Agent 偏好（仅超级用户）：自定义系统提示词编辑器，草稿 + 显式保存。
2. **偏好只持久化在本浏览器的 localStorage**（键 `signaldesk.preferences.v1`，带版本号），
   不进后端：这些值本来就随每次请求发送，后端不需要知道「用户偏好的默认值」。应用级单例
   store（`features/settings/composables/usePreferences.ts`）写入即落盘，读盘失败静默落回默认。
3. **输入区只留状态入口，不留编辑器**：Agent 输入条在提示词覆盖生效时亮一枚链回
   `/settings/agent` 的徽章；检索输入条保留一个直达 `/settings/search` 的图标入口，
   当前值放在 title 里。
4. **`useAgentChat` / `useSearchStream` 改为注入式读取偏好**（`getSystemPrompt` /
   `getDocumentLimit` 等 getter）：提交那一刻读到什么值，这一轮就用什么值。composable
   与偏好 store 保持解耦，feature 之间不互相导入，页面是唯一组合点。

## Considered Options

**留在输入区原位，只做持久化。** 改动最小，但「不可发现」这个核心问题原样保留——埋着的
配置加了持久化，只是把隐性状态变成了隐性的持久状态。

**偏好存后端（账号级设置表）。** 跨设备一致，但要新增后端能力域、迁移和接口，而这两个
偏好的消费方（每次请求）本来就由前端组装；在接入第二业务领域之前先不引入这张表。
后端持久化不与本地持久化冲突，将来要升级时 localStorage 键的版本号整体作废即可。

**两个偏好各自独立成页。** 检索偏好放检索页、提示词放 Agent 页，各贴各的场景。但「配置」
这个心智模型会被拆散——用户在 A 处改了全局默认值，到 B 处找不到它。单一设置中心让
「哪里改配置」只有一个答案。

## Consequences

**可见行为变化是有意的。** 输入区的提示词面板与检索参数 popover 移除；`/account` 重定向到
`/settings/account`；偏好跨刷新保留。自助页与账号管理页的分离原则不变（见 ADR 0011 追加节）。

**偏好是每浏览器一份的，不是账号级的。** 换浏览器、清站点数据都会回到默认值——这是本方案
的成本，换来的零后端改动。设置页文案明确说明「只保存在当前浏览器」。

**安全边界不变。** localStorage 里只有数量参数与提示词文本，密码与 Token 仍然只存在于
HttpOnly Cookie；Agent 提示词分区只对超级用户可见（路由守卫 + 页面兜底），因为
`/agent/*` 本来就只放行超级用户。前端的条件渲染是体验，不是鉴权。

**契约常量上收到 api 层。** 数量参数边界与提示词上界是请求契约的一部分，从 feature 的
validation 模块移到 `api/document-search.ts` 与 `api/agent-chat.ts`——设置中心是它们的
第二个消费方，事实源只有一份。

**消融记录。** 评估过给设置保存配全局 Toast 通知：检索偏好是改动即生效（无「保存」动作），
提示词保存用 2.5 秒的内联确认足够，全局通知体系（ToastContainer/useToast）在全站零调用方，
随本决策删除而不是启用。BasePopover 因检索参数 popover 移除而失去唯一消费方，一并删除。
