# 会话历史不随历史摘要缩减

会话历史和上下文记录从这一刻起是两份不同的东西：界面上永远能回看到一次会话的全部轮次，历史摘要只决定模型能看到什么。这是对 [0021](0021-agent-run-evidence-and-replay.md) 末段的修订——那句「早期问答和引用不再逐条回看」把「旧证据不送给主模型」这条约束顺手扩大成了「用户也看不到」，而两件事没有必然联系：模型该忘掉什么，不该决定用户还能查到什么。

用户回看历史是为了核对自己看到过什么、它答过什么，这份事实与模型的记忆预算无关。业界（Claude Code 把完整记录写在自己的 transcript 里、同类产品做自动压缩时只压送去模型的那份）都是保留完整记录、在界面上画出压缩分界。

**代价必须成对记住**：界面显示的内容会比模型记得的多。用户拿着分界线之前的原文追问时，模型很可能答不上来——这正是 0021 当年要回避的场景。应对办法是在界面上如实标出压缩分界，而不是删掉原文去维持一个假的等式。

## Considered Options

**维持现状：压缩即删除，界面即模型所见。** 界面与模型上下文严格一致，用户问不出「模型不知道、屏幕上却写着」的问题；代价是用户的对话记录被模型预算牵着走，长会话里早期内容永久消失。0021 选的是它。

**把压缩推迟、多保留几轮。** 不改变性质，只是把消失推远一点；长会话最终会撞上同一个问题。

## Consequences

压缩分界从此是界面上的一个可见事实，所以压缩动作要留下「发生在哪一轮之前」的痕迹，不能只留一条摘要消息。
