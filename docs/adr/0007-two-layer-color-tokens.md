# 颜色 token 分两层：色阶层只给 tokens.css 用，组件只用语义层

`tokens.css` 里颜色分两块：原始色阶（`--neutral-*`、`--pine-*` 这类）只允许被 `tokens.css` 自己引用，语义层（`--surface-*`、`--text-*`、`--border-*`、`--accent-*` 这类）才是组件能用的；组件里出现色阶名或裸色值都算违规，由 `shared-styles.node.spec.ts` 守住。改之前是单层，`--ink-*`、`--paper-*` 这样的名字把「浅色模式」焊进了名字本身：墨深纸浅，做深色模式时墨要变浅、纸要变深，每一处引用都要重新判断；`--text-primary` 在两个主题下都是实话，换主题只重映射语义层，组件一行不动。

同一版顺带定下三件事：强调色只有一个，砖红收窄到只报错，否则同屏两种红分不清谁是错误；阴影留在语义层，因为它带颜色、深色模式里投影要换算法；`color-scheme` 属于语义层，漏了它深色模式下原生滚动条和弹窗仍是白的。

## Considered Options

**保持单层，只把名字改中性（`--color-1` 到 `--color-9`）。** 把「名字说反话」换成「名字什么也不说」，深色模式下该不该反转仍要逐处判断。

**只留语义层，色阶直接写色值。** 同一个中性色会在语义层里被复制五六遍，调色阶时要挨个找哪些是同一个值，正是分层要避免的事。

## Consequences

加新颜色先问它属于哪一类语义，没有合适的就新增语义 token，不在组件里直接引色阶。成对反转的令牌（`--surface-inverse` 与 `--text-on-inverse`）深色映射要两端一起核，只核背景端会画出白字白底。
