# 颜色 token 分两层：色阶层只给 tokens.css 用，组件只用语义层

`frontend/src/styles/tokens.css` 里颜色分两个 `:root` 块：第一块是原始色阶（`--neutral-*`、
`--pine-*`、`--brick-*`、`--amber-*`），只允许被 `tokens.css` 自己引用；第二块是语义层
（`--surface-*`、`--text-*`、`--border-*`、`--accent-*`、`--danger-*`、`--warning-*`、`--shadow-*`），
组件只准用这一层。组件里出现 `var(--neutral-300)` 或裸色值都算违规，由
`src/styles/shared-styles.node.spec.ts` 守住。分层理由的完整说明在 `tokens.css` 文件头。

**分层的理由。** 改这一版之前是单层：`--ink-950`、`--paper-50`、`--source-600`、`--signal-500`
这样直接映射到色值。问题是这套名字把「浅色模式」焊进了名字本身——`--ink-*` 是墨、`--paper-*` 是纸，
墨深纸浅；做深色模式时 `--ink-950` 必须变成浅色、`--paper-50` 必须变成深色，于是名字全都在说反话，
每个组件里的每一处引用都要重新判断「这里的墨到底该是深还是浅」。`--text-primary` 和
`--surface-raised` 在两个主题下都是实话，换主题只重映射语义层这一块，组件一行不动。

同一版顺带定下的三件事：**强调色只有一个，砖红收窄到只报错**（原来青和红都在当强调色，同屏两种红
只靠深浅区分，谁是错误看不出来）；**阴影留在语义层**，因为它带颜色、深色模式里投影要换算法，有主题
维度，不能和 `--radius-*`、`--content-width` 那些放在一起；**`color-scheme` 属于语义层**，漏了它
深色模式下原生滚动条和 date/select 弹窗仍然是白的。

**成对反转的令牌，深色映射要两端一起核。** `--surface-inverse` 与 `--text-on-inverse` 这对
「与页面明暗相反」的令牌必须同步翻转。初版深色映射把后者写成了深色端的近似色，结果白字画白底，顶栏
品牌标识块的图形整个隐形（2026-09 审查发现）。教训是只核背景端不够。

## Considered Options

**保持单层，只把名字改中性（`--color-1` 到 `--color-9`）。** 省一层跳转。但这只是把「名字说反话」
换成「名字什么也不说」：组件里看到 `--color-7` 完全不知道它是文字还是描边，改一处得先去 tokens.css
查。而且深色模式下 `--color-7` 该不该反转仍然要逐处判断，问题没解决只是搬了个地方。

**只留语义层，色阶直接写色值。** 少一层，但同一个中性色会在语义层里被复制五六遍（`--surface-sunken`
和 `--border-subtle` 现在是同一个色阶值）。调色阶时要在语义层里挨个找哪些是同一个值，正是分层要避免
的事。

**用 CSS 相对颜色语法（`rgb(from var(--accent) …)`）代替色阶层。** 表达力更强，但可读性差，而且团队
里没人在用。相对颜色那一族的 `color-mix` 只在「兑透明度」这一种场景用得上（环境托管行的斜纹、片段与
正文区的半透凹面、引用标记），用不到它就没有理由换掉色阶层。

## Consequences

加新颜色时先问它属于哪一类语义（表面/文字/描边/强调/状态），没有合适的语义名就新增一个语义 token，
不要在组件里直接引色阶。这一版里 `--surface-sunken-hover`、`--surface-inverse`、`--text-on-inverse`
就是这样加出来的——次要按钮的静态底和悬停底如果都映射到同一个色阶值会撞成同色，而跳转链接、标识块
需要「与页面明暗相反」的一对，`--surface-raised` 顶不了：那个跟着页面走，深色模式下会变成深底深字。

对比度按语义 token 校验一次就够，不用逐个组件算。这条约束曾落到 `--text-muted` 身上（浅色模式下在
`--surface-raised` 上达不到 AA，因此只能用于纯装饰文字）；2026-09 重设计后 `--text-muted` 已不存在，
那一档拆成了 `--text-secondary` 与 `--text-tertiary`，约束随之转移。

**别名令牌已删除。** `--accent-primary`（与 `--accent` 同值）和 `--radius-full`（与 `--radius-pill`
同值）属于「一个语义两个名字」，最后一批使用方迁到正名后经确认零使用，三个覆盖块一并删除。
