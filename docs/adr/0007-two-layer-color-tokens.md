# 颜色 token 分两层：色阶层只给 tokens.css 用，组件只用语义层

`frontend/src/styles/tokens.css` 里颜色分两个 `:root` 块。第一块是原始色阶
（`--neutral-*`、`--teal-*`、`--brick-*`、`--amber-*`），只允许被 `tokens.css` 自己引用；
第二块是语义层（`--surface-*`、`--text-*`、`--border-*`、`--accent*`、`--danger*`、`--warning*`、
`--shadow-*`），组件只准用这一层。组件里出现 `var(--neutral-300)` 或裸色值都算违规。

改这一版之前是单层：`--ink-950`、`--paper-50`、`--source-600`、`--signal-500` 这样直接映射到色值。
问题是这套名字把「浅色模式」焊进了名字本身。`--ink-*` 是墨、`--paper-*` 是纸，墨深纸浅；做深色模式时
`--ink-950` 必须变成浅色、`--paper-50` 必须变成深色，于是名字全都在说反话，每个组件里的每一处引用都要
重新判断「这里的墨到底该是深还是浅」。`--text-primary` 和 `--surface-raised` 在两个主题下都是实话，
换主题只重映射语义层这一块，组件一行不动。

同一版顺带定下的三件事：

- **强调色只有一个，砖红收窄到只报错。** 原来青（`--source-*`）和红（`--signal-*`）都在当强调色，
  同屏两种红只靠深浅区分，`--danger-600` 和 `--signal-600` 谁是错误看不出来。现在主操作只有青，
  砖红只出现在报错，琥珀只出现在提醒。
- **阴影留在语义层，不算「非颜色 token」。** 阴影带颜色，深色模式里投影要换算法（提亮而非压暗），
  所以它有主题维度，不能和 `--radius-*`、`--content-width` 那些放在一起。
- **`color-scheme` 属于语义层。** 漏了它，深色模式下原生滚动条和 date/select 弹窗仍然是白的。
  以后加深色模式时，重映射语义层的那个块里要一并写 `color-scheme: dark`。

## Considered Options

**保持单层，只把名字改中性（`--color-1` 到 `--color-9`）。** 省一层跳转。但这只是把「名字说反话」换成
「名字什么也不说」：组件里看到 `--color-7` 完全不知道它是文字还是描边，改一处得先去 tokens.css 查。
而且深色模式下 `--color-7` 该不该反转仍然要逐处判断，问题没解决只是搬了个地方。

**只留语义层，色阶直接写色值。** 少一层，但同一个中性色会在语义层里被复制五六遍
（`--surface-sunken` 和 `--border-subtle` 现在是同一个 `--neutral-300`）。调色阶时要在语义层里
挨个找哪些是同一个值，正是分层要避免的事。

**用 CSS 相对颜色语法（`rgb(from var(--accent) …)`）代替色阶层。** 表达力更强，但可读性差，
而且团队里没人在用；`color-mix` 只在确实需要兑透明度的一处（环境托管行的斜纹）用了，够了。

## Consequences

加新颜色时先问它属于哪一类语义（表面/文字/描边/强调/状态），没有合适的语义名就新增一个语义 token，
不要在组件里直接引色阶。这一版里 `--surface-sunken-hover`、`--surface-inverse`、`--text-on-inverse`
就是这样加出来的——次要按钮的静态底和悬停底如果都映射到 `--surface-sunken` 会撞成同色，
而跳转链接、标识块需要「与页面明暗相反」的一对，`--surface-raised` 顶不了：那个跟着页面走，
深色模式下会变成深底深字。

对比度按语义 token 校验一次就够，不用逐个组件算。当前浅色模式下 `--text-muted` 在
`--surface-raised` 上是 3.85:1，**不到 AA 的 4.5:1**，所以它只能用于纯装饰文字；
正文与小号加粗标签一律用 `--text-secondary`（7.57:1）。这一条是这次迁移里唯一改变了视觉决策的
约束：原设计有一批小号加粗眉标签用的是红色，退红之后本来要落到 `--text-muted`，因为这个对比度
落到了 `--text-secondary`。

组件层禁止裸色值这件事由测试守，不靠自觉，见 `src/styles/shared-styles.node.spec.ts`。

## 追加（2026-09）：反转对在深色映射里拿反过一端；别名令牌进入弃用流程

- **`--text-on-inverse` 深色映射勘误。** 这对「与页面明暗相反」的令牌必须成对翻转：
  深色下 `--surface-inverse` 翻成浅色（`--neutral-900` → `#f4f5f5`），`--text-on-inverse`
  就必须翻成深色端 `--neutral-50`（此时是 `#14181a`）。初版深色映射写成了
  `--neutral-950`——它深色下是 `#fbfbfa`，结果白字画白底，顶栏品牌标识块的图形
  整个隐形（2026-09 审查发现）。教训：成对反转的令牌，加深色映射时两端要一起核，
  不能只核背景端。
- **别名令牌标弃用。** `--accent-primary`（与 `--accent` 完全同值）和 `--radius-full`
  （与 `--radius-pill` 完全同值）属于「一个语义两个名字」，最后一批使用方
  （账号设置页）已在 2026-09 迁移到正名，`src/` 下清零。tokens.css 里保留定义并注明
  弃用，给外部引用留一个过渡期；新代码禁止引用，过渡期后连同深浅两个覆盖块一起删除。
  顺带把账号设置页从这批「扩展语义表面」迁到了现行语义层写法，这类页面不再新增。
