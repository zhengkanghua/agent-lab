# 字号与字重收敛为令牌阶，不再各处写裸值

2026-09-10。全站字号令牌化、字重收敛为三档，12px 成为字号硬下限。

## 背景

改动前的实际状态：全站 216 条 `font-size` 声明里只有 7 条引用令牌，唯一值 51 个；
69 条小于 12px，26 条小于 11px，实测最小值 9.92px（结果卡上的「文档」标记）。
中文在 12px 以下笔画互相糊在一起，这不是「小一号」，是不可读。

字重更散：14 个不同值（450/560/600/640/650/680/700/710/720/740/760/780）。

命名上还有一个陷阱：`--text-*` 同时是文字颜色（`--text-primary`）和字号
（`--text-sm`）的命名空间，「`--text-sm` 是字号、`--text-primary` 是颜色」读代码时分不出来。

## 实测（决定结论的部分）

用 Chromium 在应用真实字体栈下量墨水覆盖（canvas 与 DOM 截图两法互证）。
宽度指纹显示 `system-ui`、`'Microsoft YaHei'`、`sans-serif` 三者同宽（556），
即 Windows 中文环境实际落到微软雅黑：

| 声明值 | 400 | 450 | 500 | 560 | 600 | 640 | 650 | 680 | 700 | 760 | 900 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 墨水像素 | 8380 | 8380 | 8380 | 12728 | 12728 | 12728 | 12728 | 12728 | 12728 | 12728 | 12728 |

雅黑只提供 Regular(400) 与 Bold(700) 两个字面，**560 及以上的 10 个值渲染结果完全相同**。
这不是理论推断，是量出来的：那 14 个字重在这台机器上只有两种观感。

macOS 的 SF Pro 与 Windows 的 Segoe UI 提供独立的 Semibold，600 与 700 在那些平台上可区分。

## 决策

**字号 8 档，前缀改用 `--fs-`**：`xs 12 / sm 14 / base 16 / lg 18 / xl 20 / 2xl 24 / 3xl 32 / 4xl 42`（px）。
12px 是硬下限，不再有更小的档。档位与 Tailwind、Primer 的 `--text-xs..2xl` 对齐，
不自造中间档——曾试过 13px 一档，与所有主流规范都不一致，且和 12px 的观感差异不足以支撑一档，已删。

**字重 3 档**：`--fw-normal 400 / --fw-semibold 600 / --fw-bold 700`，
命名与 Primer 的 normal / semibold / bold 一致。

**触控目标 1 档**：`--tap-target: 44px`，只在 `@media (pointer: coarse)` 里引用。

## Consequences

**字重三档是「意图」，不是「本机可区分」的承诺。** 在只提供两个字面的平台上
（Windows 中文，也就是当前主力环境）600 会与 700 并档。保留三档而不是砍成两档的理由：
macOS 上能逐档生效，且 `semibold` / `bold` 的语义差异在代码里是有意义的区分。
代价要如实记住——**在 Windows 上 `--fw-semibold` 与 `--fw-bold` 看起来一样**，
想靠字重区分两个层级时要挑别的办法（字号、颜色、留白）。

**收敛不改变桌面端的视觉结果**（原来那 14 个值本来就只渲染出两种观感），
真正变化的是「写下的值可解释了」。迁移用脚本批量完成，映射规则：
≤500 → normal，≤680 → semibold，≥700 → bold。

**`--text-*` 现在只表示颜色**，字号一律 `--fs-*`。分区隔开了，
不会再出现「按 `--text-` 前缀搜索时两种语义混在一起」的情况。

**SafeMarkdown 的 `0.82em` / `0.86em` 与 `style.css` 的 `body { font-size: 16px }` 保持裸值。**
前两个是相对父级缩放的引用标记与行内代码，缩放本身是有意的；
后者是 rem 的基准定义，令牌化会自我指涉。
