# 后台只有顶栏一个入口，设置导航不再放直达链接

2026-09-10，老板确认把后台入口收敛成唯一一个：前台顶栏一枚仅超级用户可见的图标，
指向 `/admin`；设置中心侧栏里原先的「账号管理」「定时任务」两条直达链接撤掉。

## 背景

后台 `/admin/:section?` 有五个分区：账号管理、知识库、文件资料、来源管理、定时任务。
但在这次改动之前，前台能到达后台的路径只有设置中心侧栏里那两条直达链接，
覆盖五个分区里的两个——知识库、文件资料、来源管理三个分区，
在 `/admin` 自己的侧栏之外完全不可发现。用户想管理知识库，得先知道 `/admin` 这个地址存在。
而前台顶栏根本没有指向后台的入口。

这个问题的性质是「入口的覆盖面小于内容的范围」。两条直达链接看着方便，
实际效果是给了一个不完整的心智模型：看到它的人以为后台只有这两块。

## Considered Options

**保持现状，在设置导航里补全五个分区。** 覆盖面问题解决了，但设置中心会变成后台的第二个导航，
两套侧边栏并列在同一个页面上；「设置」与「后台」这两个概念的边界也会更模糊——
知识库、文件资料这些是管理操作，不是个人设置。

**把入口收进右上角的账号菜单。** 少一处视觉噪音。但账号菜单的语义是「关于我自己」
（邮箱、改密码、退出），把管理别人和全局配置的入口塞进去，与它当前的定位相反；
而且需要先展开一层才能看到，比现在更难发现。

**顶栏给一枚仅超管可见的入口图标（选中）。** 前台三个页面共用同一个外壳，
写在 `AppShell` 里天然覆盖全部页面，不依赖任何页面记得传参数；
后台五个分区由 `/admin` 自己的侧栏承载，不再有第二份导航。

## Consequences

**入口的可见性收窄成一次判断。** 顶栏那枚图标只在 `is_superuser` 为真时渲染。
这是体验层判断，不是鉴权——真正的门仍然是路由 `meta.requiresSuperuser`
与后端 `current_superuser` 依赖。

**设置导航不再承担后台导航。** `SettingsNav` 只剩三个设置分区，
`admin-divider` / `admin-heading` 两条装饰性样式随之删除。
今后新增后台分区不需要同步改设置导航，不会再有「列表覆盖不全」这类漂移。

**与 [ADR 0011](0011-self-service-page-separate-from-user-admin.md) 追加节的一处冲突，此处显式取代。**
0011 的追加节写明：「超级用户通往 `/admin/users` 的入口从账号页里的一张卡片挪进设置导航的
『后台管理』组——『我自己』到『管别人』的路径仍在一页之内」。
本次改动撤销的正是这句：入口不再在设置导航里。0011 的其余决策全部继续有效——
自助页与账号管理页仍是两条路由、两族组件、两种危险等级，
「管别人」的动作一个都没有搬进设置中心。

**「我自己」到「管别人」的路径不再落在一页之内。** 这是本次接受的代价：
从账号安全页去后台要点一次顶栏图标（一次跳转），而不是在同一页的侧栏里点一下。
换来的是后台入口对全部五个分区、全部前台页面都成立。ADR 0011 当时把这个「一页之内」
当作必要条件，本次判断它不成立——那个条件保护的是「路径不断在半路」，
而一个只覆盖 2/5 分区的入口本身就是断的。
