# 第一版 Agent 只读

Agent 能调用的工具全部只读：不写 PostgreSQL 业务表、不写 Qdrant、不改处理状态、不触发同步或索引。这不是「第一版先少做点」的排期，而是安全边界：模型的上下文里有从外部抓来的正文，那些文字是数据不是指令，但模型没有可靠机制区分两者。只读时最坏结果是回答错误；一旦有写工具，被正文里的注入指令牵着走就会改坏库里的数据，而且改动会被后续检索读到，错误自我放大。要加写能力必须先修订本文，并一起补上权限分级、操作审计和对外部正文的注入防护，任何一项缺失就不该开。

## Considered Options

**给 Agent 一个「重新索引这篇」的工具。** 要不要重索引由 `content_hash` 比对就能确定（见 [0002](0002-frontend-detects-stale-body-by-comparing-hashes.md)），用模型的判断替换一次确定的比较，是拿不确定换确定。

**写工具做出来但默认关掉。** 那条写路径必须一直保持可工作、测试也得覆盖它，成本照付、风险照担，只是把「有没有」变成「开没开」。

**允许写但每次弹给用户确认。** 确认的人就是发起提问的人，注入的目标本来就是让请求看起来合理；同一个人点「同意」不构成第二道独立判断。
