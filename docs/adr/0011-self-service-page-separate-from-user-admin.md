# 自助账号页与账号管理页并存，不合并成一页

自助能力（关于我自己的：邮箱、角色、创建时间、改自己的密码）与账号管理（关于别人的：账号列表、建号、
停用、降级、改别人的密码、踢别人的会话）是两条路由、两族组件、两种危险等级，**不合并成一页**。自助
能力随设置中心落地后落在 `/settings/account`，`/account` 只留一条重定向；`/admin/users` 保持原样，
只承载「关于别人」。设置中心为什么要把自助能力与偏好配置收到同一个入口，见
[ADR 0018](0018-settings-hub-with-local-preferences.md)；分区划分与页面形态见
[前端 README](../../frontend/README.md)。

**为什么否掉「一页两态」。** 原始需求是「点用户信息进入统一的管理界面，普通账号只能管自己，超级用户
还能管别人」。否掉它的理由是这两块操作的性质不同：改自己密码是一次性的、低风险的、改完就走；管别人要
浏览、筛选、反复操作，还带停用和降级这种能把人锁在门外的动作。合成一页会让超级用户每次想改自己密码，
都得先在一张几十行的账号表里找到自己那一行——**而这正是当前痛点的翻版**，痛点就是「想管账号得先退回
检索页」。把入口统一到自助页已经解决了「找不到入口」，不需要再把两页的内容也叠起来。

## Considered Options

**一条路由，内容按角色伸缩。** 普通账号看到一屏自己的信息，超级用户在同一页下面多出账号表。最贴近
原始需求，只有一个地址要记。但除了上面说的「超级用户每次都要从长表里找自己」，它还有两个代价：一是
同一个地址对两类人的危险程度完全不同，普通账号看到的是个安全页面，超级用户看到的是能停用别人的控制台，
出安全事故时说不清「谁在哪一页做了什么」；二是 `UserAdminPage.vue` 和 `features/user-admin/` 整族都要
重构进新页面，改动面从「新增一个页面」扩大到「重排一个已经在用的管理流程」。

**只加自助页，不给它通往账号管理的入口，管理入口仅留在后台那一枚图标。** 少一个重复入口。但原始需求
想要的心理路径是「点我的信息 → 到管理界面」，自助页是那个落点，从这里走不到管别人的地方就断在半路。

**把自助能力做成弹窗，不新增路由。** 改密码是个短表单，弹窗够用。但账号信息（邮箱、角色、创建时间）
是「想查一眼」的内容，塞进弹窗就没有可分享、可收藏、可刷新的地址；而且弹窗里再放一个通往
`/admin/users` 的入口会很别扭。项目已有的模式是「一件事一个路由」，不为这一处破例。

**在设置导航里放一份后台直达链接。** 曾经这么做过，后来撤销：设置导航只挂了「账号管理」「定时任务」
两条，而后台有多个分区，一个只覆盖其中一小块的入口本身就是断的，而且会让设置中心变成后台的第二个
导航。**把入口收进账号菜单**也评估过：账号菜单的语义是「关于我自己」，把管理别人和全局配置塞进去与它
相反，而且要先展开一层才能看到。现在的做法是后台唯一入口放在侧栏底部、仅超管可见（仅超管可见是体验层
判断，真正的门是路由 `meta.requiresSuperuser` 与后端 `current_superuser`）。

## Consequences

**停用和降级自己只留在 `/admin/users`。** 后端目前不阻止超级用户把自己降级或停用，前端是在事后善后
（自己降级后踢回登录页）。这个现状不改，但这两个动作不复制进自助页：那一页的定位是低风险自助页，在
里面长出能把自己锁死的按钮，会让同一个地址对两类人的危险程度不同——正是上面否掉合并方案的理由之一。

**自助页的路由守卫只要求登录，不要求超级用户。** 页面对所有人都有意义。超级用户那半边的内容由前端按
`is_superuser` 决定渲不渲染，真正的门在后端：`/admin/users` 那族路由挂的是 `Depends(current_superuser)`。
前端的条件渲染是体验，不是鉴权，不能反过来依赖它。

**新增物不放进 `features/user-admin/`。** 那一族的语义是「管别人」，自助页放进去会让这个语义失效，
下一个人读目录名会以为里面的东西都需要超级用户。表单校验规则是唯一的例外：两族页面镜像的是同一套
后端密码强度规则，密码长度常量统一定义在 `shared/model/password.ts`，两边都从那里引用、不复制——
feature 之间禁止相互导入是 eslint 硬规则，共享只能下沉 shared。

**「改密码」有两个入口，这是接受的重复。** 超级用户改自己的密码可以走 `/settings/account`，也可以在
`/admin/users` 里找到自己那一行改。后者是管理动作的一致性（表格里每一行都能改密），前者是自助路径。
两者调的是不同接口——自助那条（`POST /auth/me/password`）要校验旧密码，管理那条
（`POST /admin/users/{user_id}/password`）不校验（超级用户本来就有权限），所以它们不是同一个功能的
两个入口，而是两个不同的功能。
