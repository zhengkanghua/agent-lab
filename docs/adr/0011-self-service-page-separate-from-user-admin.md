# 自助账号页与账号管理页并存，不合并成一页

自助能力（关于我自己的：看信息、改自己的密码）落在 `/settings/account`，账号管理（关于别人的：建号、停用、降级、改别人的密码、踢会话）留在 `/admin/users`，两条路由、两族组件、两种危险等级，不合并成一页。原始需求是「点用户信息进入统一的管理界面，普通账号只能管自己，超级用户还能管别人」，否掉它是因为这两块操作性质不同：改自己密码是一次性的、低风险的、改完就走；管别人要浏览、筛选、反复操作，还带能把人锁在门外的动作。合成一页会让超级用户每次想改自己密码都得先在几十行的账号表里找到自己那一行，而且同一个地址对两类人的危险程度完全不同，出事故时说不清谁在哪一页做了什么。

## Considered Options

**把自助能力做成弹窗，不新增路由。** 账号信息是「想查一眼」的内容，塞进弹窗就没有可分享、可收藏、可刷新的地址；项目的模式是一件事一个路由。

**在设置导航里放一份后台直达链接。** 曾经这么做过，后来撤销：后台有多个分区，一个只覆盖其中一小块的入口本身就是断的，还会让设置中心变成后台的第二个导航。现在后台唯一入口放在侧栏底部、仅超管可见。

## Consequences

停用和降级自己只留在 `/admin/users`，不复制进自助页：低风险自助页里长出能把自己锁死的按钮，正是否掉合并方案的理由。自助页的路由守卫只要求登录，超级用户那半边由前端按角色决定渲不渲染，那是体验不是鉴权，真正的门在后端。「改密码」有两个入口是接受的重复，但它们不是同一个功能：自助那条要校验旧密码，管理那条不校验。
