# 自助账号页与账号管理页并存，不合并成一页

`/account` 是人人可进的自助页，只承载「关于我自己」：邮箱、角色、创建时间和改自己的密码。
`/admin/users` 保持原样，只承载「关于别人」：账号列表、建号、停用、降级、改别人的密码、踢别人的会话。
两条路由并存，两套组件互不复用。顶栏那串账号邮箱指向 `/account`；超级用户在 `/account` 里多一个
通往 `/admin/users` 的入口，把「我自己」到「管别人」这一步接起来。

原始需求是「点用户信息进入统一的管理界面，普通账号只能管自己，超级用户还能管别人」——即一页两态。
否掉它的理由是这两块操作的性质不同：改自己密码是一次性的、低风险的、改完就走；管别人要浏览、
筛选、反复操作，还带停用和降级这种能把人锁在门外的动作。合成一页会让超级用户每次想改自己密码，
都得先在一张几十行的账号表里找到自己那一行——**而这正是当前痛点的翻版**，当前痛点就是「想管账号
得先退回检索页」。把入口统一到 `/account` 已经解决了「找不到入口」，不需要再把两页的内容也叠起来。

## Considered Options

**一条路由 `/account`，内容按角色伸缩。** 普通账号看到一屏自己的信息，超级用户在同一页下面多出
账号表。最贴近原始需求，只有一个地址要记，路由守卫也只需 `requiresAuth`。但除了上面说的「超级用户
每次都要从长表里找自己」，它还有两个代价：一是同一个地址对两类人的危险程度完全不同，普通账号看到的
是个安全页面，超级用户看到的是能停用别人的控制台，出安全事故时说不清「谁在哪一页做了什么」；
二是 `UserAdminPage.vue` 和 `features/user-admin/` 整族都要重构进新页面，改动面从「新增一个页面」
扩大到「重排一个已经在用的管理流程」，而那个流程眼下没有任何问题。

**只加自助页，不给它通往账号管理的入口，管理入口仅留在顶栏图标。** 少一个重复入口。但原始需求想要的
心理路径是「点我的信息 → 到管理界面」，`/account` 是那个落点，从这里走不到管别人的地方就断在半路。
顶栏图标是给已经知道路的人用的快捷方式，两者服务的不是同一个时刻。

**把自助能力做成弹窗，不新增路由。** 改密码是个短表单，弹窗够用，且任何页面都能唤起。但账号信息
（邮箱、角色、创建时间）是「想查一眼」的内容，塞进弹窗就没有可分享、可收藏、可刷新的地址；而且
弹窗里再放一个通往 `/admin/users` 的入口会很别扭。项目已有的模式是「一件事一个路由」
（`/agent/:threadId` 那条注释写明了可刷新是基本预期），不为这一处破例。

## Consequences

**停用和降级自己只留在 `/admin/users`。** 后端目前不阻止超级用户把自己降级或停用，前端是在事后善后
（自己降级后踢回登录页）。这个现状不改，但这两个动作不复制进 `/account`：那一页的定位是低风险自助页，
在里面长出能把自己锁死的按钮，会让同一个地址对两类人的危险程度不同——正是上面否掉合并方案的理由之一。
`/admin/users` 从名字到内容都在说「你在做管理操作」，留在那里更诚实。

**`/account` 的路由守卫只要求登录，不要求超级用户。** 页面对所有人都有意义。超级用户那半边的内容
由前端按 `is_superuser` 决定渲不渲染，真正的门在后端：`/admin/users` 那族路由挂的是
`Depends(current_superuser)`。前端的条件渲染是体验，不是鉴权，不能反过来依赖它。

**新增物不放进 `features/user-admin/`。** 那一族的语义是「管别人」，自助页放进去会让这个语义失效，
下一个人读目录名会以为里面的东西都需要超级用户。表单校验规则是唯一的例外：两族页面
镜像的是同一套后端密码强度规则，密码长度常量统一定义在 `shared/model/password.ts`，
两边都从那里引用，不复制——feature 之间禁止相互导入是 eslint 硬规则，共享只能下沉 shared。

**两页并存意味着「改密码」这件事有两个入口。** 超级用户改自己的密码可以走 `/account`，也可以在
`/admin/users` 里找到自己那一行改。这是接受的重复：后者是管理动作的一致性（表格里每一行都能改密），
前者是自助路径。两者调的是不同接口——自助那条要校验旧密码，管理那条不校验（超级用户本来就有权限），
所以它们不是同一个功能的两个入口，而是两个不同的功能。

## 追加（2026-09，随 ADR 0018 的设置中心）

`/account` 整体并入设置中心，成为 `/settings/account`（账号安全分区），旧地址重定向保留。
本文的核心决策不变且更成立：自助页（设置中心的账号分区）与账号管理页（`/admin/users`）
仍是两条路由、两族组件、两种危险等级；「管别人」的动作一个也没有搬进设置中心。

两处随迁移调整：超级用户通往 `/admin/users` 的入口从账号页里的一张卡片挪进设置导航的
「后台管理」组——「我自己」到「管别人」的路径仍在一页之内；`features/account` 目录整体
并入 `features/settings`（自助能力现在是设置中心的一个分区，语义一致），其内部的
PasswordChangeForm、校验规则与密码常量的约束照旧。
